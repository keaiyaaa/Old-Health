## 1. 模块职责与边界

### 1.1 职责

**合规命门所在。** 本模块承担三件事：

1. 让用户理解这个工具**不能做什么**（免责与知情同意）
2. 拿到**合法有效的授权**（产品同意 + 敏感个人信息单独同意 + 老人知情）
3. 让授权**可撤回、可查询、可删除**

这是全项目**合规成本最高**的模块，也是最不能省工的地方。

### 1.2 明确不做

| 不做 | 理由 |
|---|---|
| 不做"一键同意全部" | 敏感个人信息必须**单独同意**（PIPL 第 29 条） |
| 不把老人知情藏在长条款里 | 必须独立成步（见 `../../PROJECT_REQUIREMENTS.md` 9.2.2） |
| 不做默认勾选 | 同意必须是主动行为 |
| 不做"不同意就退出"的胁迫式设计 | 但敏感信息不同意则功能确实不可用，需**明确说明原因** |
| ~~不做账号密码登录~~ | **2026-09-28 已改**：注册用邮箱 + 验证码，**登录用密码**；验证码仅注册与忘记密码场景（决策 #18） |
| 不做第三方登录（微信 / 支付宝） | 会引入额外的数据共享，一期不做 |
| 不做老人账号 | 老人端用家属账号登录后选择"我是哪位老人"，老人不注册（决策 #18） |

### 2.1 首次引导 6 步（A.3）

1. 家属注册 / 登录
2. 产品说明 + 免责声明（明确"不是医疗器械，不做诊断"）
3. **知情同意（双层）**：家属授权 + 老人知情（老人版大字 + 语音朗读）+ **敏感个人信息单独同意**
4. 添加被记录者（昵称、年龄段、方言、有无听力问题）
5. **绑定老人端设备**（邀请码 / 扫码），并在老人手机上完成首次录音示范
6. 设置提醒时间，结束

## 3. 同意模型（本模块的核心）

### 3.1 四层同意，互相独立

| 层 | 同意内容 | 必需 | 可单独撤回 | 撤回后果 |
|---|---|---|---|---|
| L1 | 用户协议 + 隐私政策 | 是 | 否（撤回＝注销） | 账号注销 |
| L2 | **敏感个人信息处理**（语音、认知健康信息） | 是 | **是** | 服务不可用（录音本身就是敏感信息），需明确告知 |
| L3 | **老人知情**（第三方个人信息） | 是 | 是 | 停止采集，已采数据按老人意愿处理 |
| L4 | 研究数据使用 | 否 | 是 | 停止研究使用，已导出匿名数据集按伦理承诺处理 |

**关键设计：L2 与 L3 必须独立成页、独立勾选、独立留痕。** 不能合并成"我同意以上全部"。

### 3.2 老人版知情同意的特殊要求

| 要求 | 实现 |
|---|---|
| 大字 | 正文 ≥20sp（比老人端常规更大） |
| 可朗读 | 必须有 TTS 播放按钮，且是**默认触发**（进入页面即询问是否朗读） |
| 用词 | 不出现"评估/测试/检查/筛查/诊断" |
| 语言 | 一句话说清："这是留给家里人的声音记录" |
| 撤回入口 | 老人端设置页常驻，**一眼可见** |

**文案示例**（老人版）：

> 您说的话会录下来，存起来。
> 您的家人可以听到，别人听不到。
> 这不会给您做任何检查，也不会说您有没有病。
> 您随时可以让我停下，随时可以删掉。

### 3.3 同意状态的可查询性

用户必须能在 P-F7 / P-E4 看到：

- 我同意了哪几项、什么时候同意的
- 每项能否撤回、撤回后会发生什么
- 撤回按钮**就在旁边**

**这三点缺一不可。** 只给"已同意"的状态而不给撤回入口，等于没有撤回权。

## 4. 角色与权限

| 操作 | `ELDER` | `CG_EDITOR` | `CG_READONLY` | `RESEARCHER` |
|---|---|---|---|---|
| 查看同意状态 | ✅（自己的） | ✅ | ✅ | ✅（研究项） |
| 撤回 L2 敏感信息同意 | ✅ | ❌ | ❌ | ❌ |
| 撤回 L3 老人知情 | ✅ | ❌ | ❌ | ❌ |
| 撤回 L4 研究同意 | ✅ | ❌ | ❌ | ✅（作为研究方） |
| 注销账号 | ✅（自己的） | ✅（自己的） | ✅（自己的） | ✅ |
| 改留存期限 | ✅ | ✅ | ❌ | ❌ |
| 全量导出 | ✅ | ✅ | ✅ | ✅ |
| 清空全部记录 | ✅ | ❌ | ❌ | ❌ |

**撤回 L2 / L3 只能由被记录者本人操作**（见 `../../PROJECT_REQUIREMENTS.md` 2.5）。家属不能替老人撤回，也不能阻止老人撤回。

### 5.1 `DangerZone` 的设计要求

删除与注销是**不可逆操作**，UI 必须：

1. 与其他设置**视觉隔离**（单独区块，不混在列表里）
2. 二次确认弹窗，说明**具体会删掉什么**（不是"确定吗"）
3. 高风险项（清空全部、注销）需**输入确认词**（如输入"删除"）
4. 注销额外有 **7 天冷静期**，期间可撤销
5. **不使用红色**（全站红线）——用深暖色 + 明确文案替代

## 8. 异常状态与降级

| 异常 | 表现 | 降级 |
|---|---|---|
| 拒绝敏感信息同意 | 明确说明"因为录音本身就是敏感信息，不同意则无法使用录音功能" | 允许浏览产品介绍后退出 |
| 老人拒绝知情 | 不采集；已采集数据按老人意愿删除 | 家属端明确显示"老人尚未同意" |
| TTS 不可用 | 降级为纯文字大字版 | 不阻塞流程 |
| 注销时网络失败 | **不允许"稍后重试"了事** —— 记录待删除任务，并在下次联网时自动完成；同时本地立即清除 | 显示"删除将在联网后完成，本地数据已清除" |
| 验证码收不到 | 提供重发与语音验证码 | — |
| 注销冷静期内登录 | 提示可撤销注销 | — |

### 8.1 注销的网络失败处理（容易做错）

如果注销请求因网络失败就返回"失败，请重试"，用户会以为没删掉。正确做法：

1. 本地数据**立即清除**（不等服务端）
2. 在本地持久化一条"待删除"任务，联网后自动重试
3. 界面明确告知："本地数据已删除，云端删除将在联网后自动完成"
4. 服务端必须保证删除请求**幂等**

## 11. 验收标准

- [ ] 首次引导 ≤6 步完成（NFR-3.2）

- [ ] 同意状态可查询：同意了什么、何时同意、能否撤回、撤回后果
