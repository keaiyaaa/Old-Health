# 模块：录音采集与上传

**覆盖需求**：FR-1（录音采集）、FR-6.1（离线优先）、FR-6.2（本地缓存加密）、FR-6.5（同步状态可视化）
**覆盖页面**：P-E1 录音页、P-E2 完成页、P-E3 日历页
**路由**：`elder/record`、`elder/done/{recordId}`、`elder/calendar`

---

## 1. 模块职责与边界

### 1.1 职责

让一位 78 岁、不熟练智能手机、可能带方言口音、听力略有下降的老人，在**零压力**的前提下完成一次语音记录，并保证这段音频**在任何情况下都不丢失**。

### 1.2 明确不做

| 不做 | 理由 |
|---|---|
| 不做实时波形频谱展示 | 会让老人以为在"被分析"，且增加渲染负担（NFR-2.7） |
| 不做倒计时压力 | 见 `../../PROJECT_REQUIREMENTS.md` 2.2 用户心理 |
| 不做音量"合格/不合格"提示 | 是评分暗示，属于"零评判"红线 |
| 不做失败弹窗 | 老人会以为弄坏了手机，然后不敢再用 |
| 不做录音评分、不做"录得好"评价 | 同上 |
| 不做端侧 ASR | X-9，走云端 |

## 2. 页面与路由

| 页面 | 路由 | 进入方式 | 离开方式 |
|---|---|---|---|
| P-E1 录音页 | `elder/record` | 老人端唯一首页；启动即落在此页 | 点录音按钮进入录音中态（同页状态切换，不跳路由） |
| P-E2 完成页 | `elder/done/{recordId}` | 录音正常结束后 | "完成"返回 `elder/record`；"重录"回到录音态（限 1 次） |
| P-E3 日历页 | `elder/calendar` | 从 P-E1 进入 | 返回 `elder/record` |

**P-E1 是状态机页面而非多路由**：未录 / 录音中 / 待上传 / 已完成 四种态在同一路由内切换，避免老人感知到"跳来跳去"。

## 3. 角色与权限

| 角色 | 可录音 | 可回放 | 可删除 |
|---|---|---|---|
| `ELDER` | ✅ | ✅（自己的） | ✅（自己的） |
| `CAREGIVER_EDITOR` | ✅（代录，标记 `recorderRole=CAREGIVER`） | ✅ | ❌（见 `../../PROJECT_REQUIREMENTS.md` 2.5） |
| `CAREGIVER_READONLY` | ❌ | ✅ | ❌ |
| `RESEARCHER` | ❌ | 匿名只读 | ❌ |

**前端实现要点**：老人端界面**不渲染任何权限判断逻辑的痕迹**。权限判定结果只影响"代录入口是否出现"，不影响老人端的录音主流程。

## 5. 状态管理

### 5.1 状态来源

```
ElderRecordViewModel
├── 录音状态：Idle | Recording | Saving | Done   （UI 状态，不持久化）
├── 已录时长：每秒 tick（仅用于时长环）
├── 当前话题卡：本地话题库轮换（不请求网络）
├── 待上传队列：本地 Room 表，WorkManager 消费
└── 同步状态：来自本地队列 + 服务端回执
```

**单一数据源**：录音记录以**本地 Room** 为准，云端为同步目标。这与"云端真源"的整体架构不冲突——本地是**写入真源**，云端是**汇总真源**。

### 5.2 关键设计：音频先落盘再处理

```
按下"开始说话"
  → 创建本地记录（syncState = LOCAL_ONLY）
  → MediaRecorder 直接写入 app 私有目录的加密文件
  → 录音中每 2 秒 flush，保证异常退出不丢

按下"说完了"
  → 停止录音 → 落盘完成
  → 写入 Room（记录元数据；声学指标不在端侧算——C5，2026-09-28 已上收云端）
  → 投递 WorkManager 上传任务（可延迟、可重试）
  → 跳转 P-E2
```

> **⚠️ 2026-09-28 变更（C5）**：端侧不再计算任何声学指标，登记接口也不再携带指标字段。
> 录音结束后客户端直接进入"等待分析"状态，全部指标（声学 + 文本）由云端 worker 统一计算，
> 结果经 2.3 状态轮询获取。原 FR-2.1「端侧 ≤5 秒出结果」作废，时效改为网络往返。

**硬规则**：任何一步失败都**不影响音频文件已经存在**这个事实。上传失败只是 `syncState` 变化，不改变录音已完成。

### 5.3 缓存策略

| 数据 | 位置 | 加密 |
|---|---|---|
| 音频文件 | app 私有目录 | `EncryptedFile`（AES-GCM） |
| 记录与指标 | Room | SQLCipher |
| 话题库 | Room（随版本预置） | 非敏感，可不加密 |
| 上传队列 | Room + WorkManager | SQLCipher |

## 6. 接口依赖

> 接口定义以 `../../api/` 为准，本节只声明依赖关系。

| 时机 | 接口 | 文件 |
|---|---|---|
| 录音前 | `POST /v1/records/upload-url` 获取预签名地址 | `../../api/API-02-录音与上传.md` |
| 上传 | 直传对象存储（不经业务服务器） | 同上 |
| 登记 | `POST /v1/records` 登记记录并触发分析 | 同上 |
| 轮询 | `GET /v1/records/{id}/status` | 同上 |
| 列表 | `GET /v1/records?subjectId=&from=&to=` | `../../api/API-04-记录与事件.md` |
| 删除 | `DELETE /v1/records/{id}` | 同上 |

**离线时的行为**：所有请求进入本地队列，联网后按序重放。`upload-url` 需在联网时重新获取（签名有时效，不得缓存复用）。

## 7. 异常状态与降级

| 异常 | 表现 | 降级 |
|---|---|---|
| 无麦克风权限 | 引导授权页，**不用错误语气** | 授权后回到原状态 |
| 麦克风被占用 | "等一下再试试" | 保留话题卡，不丢状态 |
| 录音中途退出 App | 自动保存已录部分 | 回到 P-E1，显示"上次那段已经存好了" |
| 录音时长 <10 秒 | **静默丢弃，不提示失败** | 回到未录态 |
| 录音时长 10–15 秒 | 保留但标记存疑，不计入趋势 | 正常流程 |
| 磁盘空间不足 | 优先提示清理，不丢已有音频 | — |
| 断网 | **录音完全正常**，标记待上传 | 联网后自动补传 |
| 上传失败 | 指数退避重试（有限次） | 超限后标记 `FAILED`，在 P-F7 可见，老人端不提示 |
| 电量过低/后台被杀 | WorkManager 持久化任务，重启后继续 | — |

**降级原则**：老人端永远只呈现"好消息或中性消息"。所有技术性失败在**家属端** P-F7 集中呈现。

## 8. 响应式与可访问性

| 项 | 要求 |
|---|---|
| 字号 | 默认"大"档；正文 ≥18sp，按钮 ≥20sp；三档可调 |
| 对比度 | ≥4.5:1 |
| 点击区 | 录音按钮 ≥120dp；其他 ≥48dp |
| 单手操作 | 录音按钮位于屏幕下半区 |
| TTS | 话题卡、按钮、反馈文案均可朗读 |
| 动效 | 支持系统"减少动态效果"；录音中动效幅度克制 |
| 布局 | 锁定竖屏；不横屏；无滑动切换 |
| 大屏/折叠屏 | 不改变布局，只增大留白 |

## 10. 验收标准

- [ ] 从打开 App 到开始录音 ≤2 次点击（FR-1.1）

- [ ] 话题卡 ≥30 条，轮换不重复，支持自定义（FR-1.2）
- [ ] 录音时长 10 秒–5 分钟，超时自动结束且给正向提示（FR-1.3）
- [ ] 录音中断/闪退后，已录部分可恢复（FR-1.4）
- [ ] **断网状态下完成录音全流程，无任何功能降级**（FR-6.1 / E2E-02）
- [ ] 音频文件使用 `EncryptedFile` 加密存储（FR-6.2）
- [ ] ~~声学指标在录音结束后 ≤5 秒出结果~~ **已随 C5 作废（2026-09-28）**：端侧不算指标，客户端在登记后正确进入"等待分析"状态，指标经轮询获取
- [ ] 老人端**全程无错误提示、无红色、无倒计时、无评分**
- [ ] 上传失败时老人端不提示，家属端 P-F7 可见（FR-6.5）
- [ ] P-E3 日历**不做颜色深浅编码**
