**覆盖需求**：FR-5（家属端）
**覆盖页面**：P-F1 总览、P-F3 记录列表、P-F4 记录详情
**路由**：`family/overview`、`family/records`、`family/records/{recordId}`

> **⚠️ 2026-09-28 联动更新（决策 #18 及后续修正）**：
> ① 绑定方式 = 「老人名字 + 系统生成绑定代码」（不再有邀请码）；
> ② 家属端**可以代录**（`recorderRole = FAMILY_PROXY`）；
> ③ **就诊摘要已移除**（B3），原"生成就诊摘要"能力删除；
> ④ 同意挂账号（`SENSITIVE`/`ELDER_INFORMED` 仅老人端会话授予）；
> ⑤ 角色细分（CG_READONLY/CG_EDITOR）取消，绑定即可读写（后端 `账号与身份.md` 4.2）。

## 1. 模块职责与边界

### 1.1 职责

让一个在通勤路上刷手机的 42 岁子女，**在 5 秒内**回答"我妈这周正常吗"；想深究时能一路点到单条录音，听到她妈的声音。

这是整个产品的**主界面**，也是 P1（张慧敏）唯一会长期使用的部分。

### 1.2 明确不做

| 不做 | 理由 |
|---|---|
| 不做"分享到微信"的社交分享 | 分享走系统分享（导出文件），不做平台内分享链路 |
| 不做动态流 / 时间线社交 | 与工具定位冲突 |
| 不做语音转文字的逐字编辑（专业级） | 只做**轻量修正**，不做出品级校对工具 |
| 不做多老人之间的对比 | 与"个人纵向比较"定位冲突 |
| 不做老人之间的排名 | 同上 |
| 不做 P-F1 的自定义卡片布局 | 首页信息层级是设计过的，不允许用户打乱 |

## 2. 页面与路由

| 页面 | 路由 | 进入 | 关键元素 |
|---|---|---|---|
| P-F1 总览 | `family/overview` | 家属端首页 | 人物卡片（含**最近同步时间**）→ 状态横幅 → 4 张趋势缩略卡 → 提醒区 → 快捷入口 → 底部常驻"本工具不提供诊断" |
| P-F3 记录列表 | `family/records` | 从 P-F1 快捷入口 | 日期、任务类型、时长、质量标记、是否有备注 |
| P-F4 记录详情 | `family/records/{recordId}` | 从 P-F3 点击 | 播放器、转写文本、当日指标、备注与事件标注、单条删除 |

## 3. 角色与权限（2026-09-28 更新）

角色细分（`CG_READONLY` / `CG_EDITOR`）**已取消**：有效绑定即可读写（后端 `账号与身份.md` 4.2），全部操作留审计。

| 操作 | 家属端（有效绑定账号） | 老人端会话 |
|---|---|---|
| 查看总览 / 列表 / 详情 / 播放音频 | ✅ | ✅（仅所选老人） |
| 代录录音 | ✅（`FAMILY_PROXY`，2026-09-28 新增） | ✅（`ELDER_SESSION`） |
| 修正转写文本 / 添加备注与事件标注 | ✅ | ✅ |
| 删除单条记录 / 改留存期限 | ✅ | ✅ |
| **清空全部记录 / 撤回 SENSITIVE 同意** | ❌（仅老人端会话） | ✅ |
| ~~生成就诊摘要~~ | **已移除（B3）** | — |

**编辑类控件的可见性规则不变**：无权限的控件**不渲染**，而不是渲染后置灰。置灰会引发"为什么我不能点"的困惑，且暴露了功能存在性。

**多家属场景**：一个老人可被多个子女账号绑定（靠「名字 + 绑定代码」对齐）。权限在绑定关系上，不在账号上；任一账号的操作全部留审计，**没有只读/编辑的降级分支**（简化后权限只有"绑定/未绑定"两态）。

## 5. 状态管理

### 5.1 状态来源

```
FamilyOverviewViewModel
├── subject：GET /v1/subjects（当前绑定）
├── lastSyncAt：含在 subject 响应中
├── status：GET /v1/status/{subjectId}
├── thumbnails：GET /v1/metrics/{subjectId}/series?range=30d（4 次或 1 次批量）
└── pendingReminder：连续未录天数

RecordListViewModel
├── page：游标分页
├── filter：任务类型 / 时间范围 / 是否有备注
└── items

RecordDetailViewModel
├── record：单条详情（含转写、指标、标注）
├── playbackState：Idle | Preparing | Playing | Paused
└── playbackSpeed：1.0 | 0.75
```

### 5.2 缓存策略

| 数据 | 策略 |
|---|---|
| 总览数据 | 内存缓存 TTL 5 分钟；下拉刷新强制重取 |
| 记录列表 | 游标分页，本地 Room 缓存最近 200 条 |
| 音频 | **不预缓存**，按需流式播放（省流量与存储） |
| 转写文本 | 随记录缓存 |

### 5.3 播放器规格

| 项 | 要求 |
|---|---|
| 默认倍速 | 1.0x |
| 提供倍速 | 0.75x（老人语速慢、方言重时用） |
| 波形 | 可选，简化显示，不逐帧重绘 |
| 后台播放 | 支持；通知栏可控 |
| 播放失败 | 提示"网络不太好，稍后再试"，**不显示错误码** |

## 7. 异常状态与降级

| 异常 | 表现 | 降级 |
|---|---|---|
| 老人多日未同步 | 人物卡片显示"最近同步：N 天前" + 顶部提示条"数据可能滞后" | 仍显示已有数据，**绝不显示"老人没有记录"** |
| 无绑定老人 | 空态 + "绑定老人账号"入口 | — |
| 有效记录 <4 条 | 缩略卡显示"数据不足" | 不画缩略图 |
| 音频签名 URL 过期 | 自动重新获取一次 | 仍失败则提示"稍后再试" |
| 转写为空（ASR 失败） | 显示"本次文本分析未完成" | 播放与指标正常 |
| 越权访问（改 URL 里的 recordId） | 服务端返回 404 | 前端显示"找不到这条记录" |
| 网络失败 | 保留缓存 + 顶部"数据可能不是最新" | 不显示错误码 |

### 7.1 最容易做错的一条

**老人多日未同步时，绝不能显示"最近没有记录"。** 这两句话对家属的含义完全不同：

- "最近没有记录" → 老人没录 → 可能是认知问题 → 焦虑
- "最近一次同步：3 天前" → 手机没联网 → 技术问题 → 安心

前端**必须**能区分"老人没录"和"数据没同步上来"这两种情况，且文案必须明确指向后者。这是本模块最高优先级的实现要求。
