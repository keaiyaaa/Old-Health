## 1. 模块职责与边界

### 1.1 职责

把 App 里的记录，变成家属**能带进诊室的一页纸**，并把"记录"变成"行动"。

这是产品**差异化最强**的功能（竞品都没做），同时也是**合规风险最高**的功能。

### 1.2 明确不做（红线，逐条对照）

| 不做 | 理由 |
|---|---|
| **不生成任何面向医生的临床判断** | 落入《医疗器械分类目录》21-04 决策支持软件定义 |
| **不做风险分级 / 指标解读 / 检查建议** | 同上 |
| **不推荐科室以外的医疗建议**（不推荐检查项目、不推荐药物） | 需要医疗资质 |
| **不出现 MMSE / MoCA / 量表分数** | X-2 |
| **不出现"认知障碍""痴呆""阿尔茨海默"等词** | 禁用词表 |
| 不做在线挂号 / 转诊 | X-5 |
| 不做医生端账号系统 | 医生只读离线文件，不登录系统（UC-13） |

### 1.3 核心判据（写代码前必须背下来）

> **App 只搬运数据，不做解读。解读是医生的事。**

具体到实现：摘要里可以出现"语速比前 30 天慢"（这是**事实描述**），不可以出现"语速下降提示认知功能可能减退"（这是**解读**）。两者的差别不是措辞，是**有没有因果与判断**。

## 3. 就诊摘要的内容边界

### 3.1 允许的内容

| 区块 | 内容 | 性质 |
|---|---|---|
| 基本信息 | 昵称、年龄段、方言、听力情况 | 事实 |
| 主诉 | **家属自己填写的**一段话 | 家属陈述 |
| 记录完成度 | 记录天数、总条数、有效条数、缺失分布 | 事实 |
| 指标趋势 | 折线图 + 基线带（**无坐标轴数值**） | 事实 |
| 事件时间轴 | 感冒 / 搬家 / 住院 / 旅行 | 事实 |
| 家属观察 | 家属填写的备注汇总 | 家属陈述 |
| 想问的问题 | 家属自己列的问题清单 | 家属陈述 |

### 3.2 禁止的内容

| 禁止 | 原因 |
|---|---|
| 任何风险分级、概率、评分 | 诊断性输出 |
| 任何指标解读文字（"这提示…"） | 解读 |
| 任何检查建议（"建议做 MoCA"） | 医疗建议 |
| 任何疾病名称 | 禁用词表 |
| 任何"医生请注意"式的提示语 | 越权指导医疗行为 |
| 原始数值（语速 152 字/分） | 非临床指标冒充临床数据 |

### 3.3 版式要求（P4 李医生的硬约束）

- **1–2 页**，可打印 A4
- 顺序按医生阅读习惯：基本信息 → 主诉 → 记录完成度 → 指标趋势 → 事件 → 家属观察 → 想问的问题
- **不是长图堆砌**（医生最怕家属拿一堆零散截图）
- 页脚固定一行："本材料由家属用手机应用整理，仅记录家属观察与录音记录，不构成任何医学判断。"

## 5. 组件边界

| 组件 | 级别 | 说明 |
|---|---|---|
| `MedicalPrepScreen` | 页面级 | 主页面 |
| `SummaryPreview` | 页面级 | 摘要预览（WYSIWYG，与导出一致） |
| `SummaryRenderer` | **共享（基础设施）** | 同一份渲染逻辑同时驱动预览与导出，避免"预览与导出一致性"问题 |
| `ExportService` | **共享** | PDF / 长图 / CSV 生成 |
| `ChecklistCard` | 页面级 | 就医清单 |
| `FollowUpForm` | 页面级 | 复诊回填 |
| `NonMedicalFooter` | **共享** | 页脚免责声明 |

### 5.1 关键设计：预览与导出共用渲染器

**不要写两套。** 预览用 Compose 画、导出用另一套逻辑生成 PDF，是必然会产生不一致的写法。正确做法：`SummaryRenderer` 输出一个中间表示（区块列表），预览层和导出层各自消费同一份中间表示。

## 6. 状态管理

```
MedicalPrepViewModel
├── canGenerate：有效记录数 ≥4
├── summarySections：由 SummaryRenderer 从多个数据源组装
├── exportState：Idle | Generating | Ready | Failed
└── followUp：复诊回填草稿
```

**数据组装来源**：

| 区块 | 来源 |
|---|---|
| 基本信息 | `GET /v1/subjects` |
| 记录完成度 | `GET /v1/records`（统计） |
| 指标趋势 | `GET /v1/metrics/{subjectId}/series` |
| 事件时间轴 | 记录中的 `eventTags` |
| 主诉 / 家属观察 / 想问的问题 | 本地表单 + `caregiverNote` |

## 7. 接口依赖

| 用途 | 接口 | 文件 |
|---|---|---|
| 摘要数据 | `GET /v1/records`、`GET /v1/metrics/...`、`GET /v1/status/...` | `../../api/API-03-指标与趋势.md`、`../../api/API-04-记录与事件.md` |
| 全量导出 | `GET /v1/export?subjectId=&scope=all` | `../../api/API-05-导出与注销.md` |
| 复诊回填 | `POST /v1/subjects/{id}/followup` | `../../api/API-05-导出与注销.md` |

**导出实现**：优先**客户端本地生成**（数据已在本地缓存），不依赖服务端生成文件，避免服务端产生大量临时文件与合规负担。

## 8. 异常状态与降级

| 异常 | 表现 | 降级 |
|---|---|---|
| 有效记录 <4 条 | 按钮置灰 + 说明原因 | 仍可导出"记录完成度"部分？→ **否，直接不可生成**（避免半成品误导医生） |
| 音频缺失 | 摘要仍可生成（摘要不含音频） | 全量导出时标注缺失条数 |
| 导出失败（磁盘满） | 提示清理空间 | — |
| 指标数据部分缺失 | 趋势图该点断开 + 标注 | 不插值 |
| 复诊回填未完成 | 不阻塞导出 | — |

## 9. 响应式与可访问性

| 项 | 要求 |
|---|---|
| 预览 | 家属端手机屏幕上以 A4 比例缩放预览 |
| 导出 | A4 PDF（打印用）+ 长图（分享到家庭群用） |
| 打印 | 黑白打印可读（不依赖颜色传达信息） |
| 字号 | 摘要正文字号固定（不跟随系统），保证打印版式稳定 |
| TalkBack | 预览区提供文本摘要描述 |

**黑白打印可读**这条容易被忽略：P1（张慧敏）会把长图发到家庭群，但她爸可能把它打印出来带给医生。**不依赖颜色**是硬要求。

## 10. 测试要求

| 类型 | 覆盖 |
|---|---|
| **合规测试（最重要）** | 生成 100 份不同数据的摘要，扫描禁用词表 + 扫描"解读性句式"（含"提示/说明/意味着/建议做/可能存在"），命中数为 0 |
| 单元 | 区块组装顺序、页数控制（≤2 页）、数据不足判定 |
| 一致性测试 | 预览与导出内容逐字节一致（同一渲染器） |
| 版式测试 | A4 打印、黑白打印、长图拼接 |
| 边界测试 | 0 条 / 3 条 / 4 条 / 1000 条记录；全部记录质量不合格 |
| 无障碍 | TalkBack |

### 10.1 "解读性句式"扫描清单

除了禁用词表，还要扫这些句式（它们是"解读"的语言特征）：

```
提示、说明、意味着、表明、反映、可能存在、可能存在、建议做、建议进行、
需要注意、值得关注、存在……的风险、符合……的特征、与……相关
```
