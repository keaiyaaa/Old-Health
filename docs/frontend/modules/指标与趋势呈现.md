# 模块：指标与趋势呈现

**覆盖需求**：FR-2（语音分析）、FR-3（基线与趋势）
**覆盖页面**：P-F2 趋势详情；同时为 P-F1 提供 4 张趋势缩略卡
**路由**：`family/trend/{metricKey}`

---

## 1. 模块职责与边界

### 1.1 职责

把算法算出来的 6 个原始指标，翻译成子女**看得懂、不会误解、不会被吓到**的趋势信息。

**本模块是整个产品合规风险的集中地。** 一句话概括职责：**呈现"和平时不一样"，绝不呈现"好不好"。**

### 1.2 明确不做（红线）

| 不做 | 理由 |
|---|---|
| **不显示任何原始数值**（如"语速 152 字/分"） | 数值会被当成测量结果，构成隐含的评估 |
| **不显示基线均值、标准差、z 分数** | 同上；`zScore` 只用于内部计算 |
| **不显示量表分数**（MMSE / MoCA / AD8） | X-2 |
| **不使用"正常/异常/偏低/偏高"** | 是判断，不是描述 |
| **不做跨人对比**（"同龄人平均"） | 与"个人纵向比较"定位冲突，且构成常模评估 |
| 不做预测、不做外推、不做"未来趋势"虚线 | 预测即诊断 |
| 不做排行榜、不做成就徽章 | 与"零评判"冲突 |
| 不使用红色 | 全站红线 |

## 2. 页面与路由

| 页面 | 路由 | 说明 |
|---|---|---|
| P-F2 趋势详情 | `family/trend/{metricKey}` | `metricKey` ∈ `SPEECH_RATE` / `PAUSE` / `VOCAB` / `COHERENCE` |
| P-F1 缩略卡 | `family/overview` 内嵌 | 只显示方向箭头 + 文字状态，点击进 P-F2 |

**`metricKey` 是稳定枚举**，与 `../../api/API-03-指标与趋势.md` 保持一致。新增指标必须同步改 `../../api/`。

## 3. 角色与权限

| 角色 | 可看趋势 | 说明 |
|---|---|---|
| `ELDER` | ⚠️ 默认**不可看** | 仅当本人在 P-E4 主动开启"我知情、我想看"开关后可见 |
| `CAREGIVER_READONLY` | ✅ | 只读 |
| `CAREGIVER_EDITOR` | ✅ | 只读（趋势不可编辑） |
| `RESEARCHER` | ✅（匿名） | 研究模式下可见 |

**关键**：老人端即使开启开关，也**只显示 P-F2 的白话部分**，不显示任何图表数值与 z 分数。P3（张建国）想看的是"有没有变化"，不是"变化了多少"。

## 5. 状态管理

### 5.1 状态来源

```
TrendViewModel
├── metricKey（路由参数）
├── range：7d | 30d | 90d（默认 30d）
├── series：来自 GET /v1/metrics/{subjectId}/series
├── baseline：来自 GET /v1/metrics/{subjectId}/baseline
├── status：来自 GET /v1/status/{subjectId}
└── events：来自记录列表中的 eventTags
```

**趋势数据不本地缓存计算**，只缓存服务端返回值（TTL 5 分钟）。原因：基线是滚动更新的，本地重算会与服务端不一致。

### 5.2 指标 → 展示名映射

| metricKey | 展示名 | 模态 | 白话解释 |
|---|---|---|---|
| `SPEECH_RATE` | 说话速度 | 声学 | "平时 1 分钟约说 180 个字，本周平均 150 个。" |
| `PAUSE` | 说话流畅度 | 声学 | "说话中间停下来的次数比平时多了一些。" |
| `VOCAB` | 用词丰富程度 | 文本 | "这周用的不一样的词比平时少了一点。" |
| `COHERENCE` | 说话的连贯性 | 文本 | "句子的连接比平时松了一些，说到后面容易换话题。" |

**白话解释文案必须走 `ui/copy/`**，不得硬编码在组件里（否则禁用词扫描扫不到）。

### 5.3 数据充分度规则（FR-3.3）

| 有效记录数 | 表现 |
|---|---|
| 0 | 全屏空态："先录第一条吧" |
| 1–3 | 充分度条红色缺失段 + 全部指标标"数据不足，仅供参考" + **不画折线** |
| ≥4 | 正常呈现 |

**充分度条不可关闭、不可隐藏、不可折叠。** 这是防止"3 条记录就下结论"的关键设计。

### 5.4 数值泄露的三层防护

这是本模块最重要的实现要求。**三层都要有，不能只靠自觉：**

| 层 | 措施 |
|---|---|
| 1. 类型层 | 视图模型只暴露 `TrendDirection` / `StatusLevel` / `PlainText`，**不暴露 `Float`**。原始数值在 Mapper 里就被消费掉，不进 UI 层 |
| 2. 组件层 | `TrendArrow`、`PlainLanguageCard` 的入参类型里**没有数字字段** |
| 3. 运行时兜底 | `ForbiddenValueGuard` 在 Debug 构建下扫描渲染树文本节点，发现数字形态的指标值即抛异常 |

**为什么需要第 3 层**：需求会变、新人会加字段。前两层靠设计纪律，第三层靠机制。

### 5.5 空值与部分失败

| 情况 | 表现 |
|---|---|
| 文本指标为 `null`（ASR 失败） | 该 Tab 显示"本周文本分析未完成"，**不显示 0、不显示空折线** |
| 部分记录质量不合格 | 折线上该点断开（不插值），并说明"有 N 次记录因音质原因未计入" |
| 老人多日未同步 | 图表右侧留白 + 顶部提示"最近同步：N 天前，数据可能滞后" |

## 6. 接口依赖

| 用途 | 接口 | 文件 |
|---|---|---|
| 时间序列 | `GET /v1/metrics/{subjectId}/series?key=&range=` | `../../api/API-03-指标与趋势.md` |
| 基线 | `GET /v1/metrics/{subjectId}/baseline` | 同上 |
| 状态 | `GET /v1/status/{subjectId}` | 同上 |
| 事件标注 | `GET /v1/records?...`（含 eventTags） | `../../api/API-04-记录与事件.md` |

**契约要点**：服务端返回**原始数值**（`Float?`），前端负责"不显示数值"的呈现规则。这是刻意的分工——数值留在数据层做计算与调试，不进视图层。

---

## 7. 异常状态与降级

| 异常 | 表现 | 降级 |
|---|---|---|
| 接口失败 | 保留上次成功数据 + 顶部"数据可能不是最新" | 不显示错误码 |
| 数据不足（<4 条） | 强制"数据不足"态 | 不画图 |
| 文本指标 `null` | 该 Tab 提示未完成 | 声学 Tab 正常 |
| 事件标注为空 | 不显示事件图层，不显示空图例 | — |
| 老人未同步 >3 天 | 顶部黄色提示条 + 时间戳 | 仍显示已有数据 |
| 状态为 S5 | 图表上方出现行动按钮，但**图表本身不加任何警示色** | — |

## 8. 响应式与可访问性

| 项 | 要求 |
|---|---|
| 图表宽度 | 360dp–600dp 自适应；折叠屏展开态可加宽 |
| 横屏 | 家属端允许横屏，横屏时图表占满宽度 |
| 图表可读性 | 折线 ≥2dp；基线带对比度 ≥3:1；**不依赖颜色单独传达信息**（同时用线型/标签） |
| 色觉障碍 | 状态同时用文字标签，颜色只是辅助 |
| TalkBack | 图表提供文本替代描述（"最近 30 天，说话速度与基线基本一致"） |
| 动态字体 | 支持系统字号放大到 200% 不截断 |

**色觉障碍这条很关键**：产品已经不用红色，如果还只靠橙/绿区分状态，色盲用户会完全无法分辨。所有状态必须**文字优先，颜色其次**。
