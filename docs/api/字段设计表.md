# 字段设计表（数据字典）

**最后更新**：2026-09-28
**地位**：`docs/api/` 是接口唯一事实来源，本表是其中**字段层的唯一事实来源**。前后端、客户端模型的字段命名、类型、可空性都以本表为准。

> **⚠️ 2026-09-28 联动更新（决策 #18 及后续修正）**：`RecorderRole` 枚举更名为 `ELDER_SESSION` / `FAMILY_PROXY`；
> `MetricKind` 枚举对齐后端 `metric_key`（SPEECH_RATE / PAUSE / VOCAB / COHERENCE）；
> `TaskType` 补齐 `WEEKLY_FREE`（一期 4 种）；S5 的 `actionRoute` 由 `family/visit_prep` 改为 `family/records`（B3：就诊摘要与就医准备页已移除）。

---

## 1. 强制规则（所有开发必须遵守）

1. **新增或修改任何字段前，先改本表**；改完本表再改代码。禁止"先写代码再补表"。
2. 字段变更必须**四处联动**，缺一即为未完成：
   - 本表
   - 客户端模型：`android/frontend/app/src/main/java/com/cognidiary/app/data/model/Models.kt`
   - 对应接口文件：`docs/api/API-0x-*.md`（按业务域归属）
   - OpenAPI：`docs/api/openapi/`（后端生成后；生成物不得手改）
3. **前后端字段必须逐字一致**：命名、类型、可空性、枚举值。联调前按第 7 节清单核对，不允许出现"字段名对不上 / 类型不一致 / 枚举值缺失"这类连接错误。
4. 第 6 节**禁止字段清单**中的任何字段，任何接口、任何模型都不允许出现。
5. 本表位于 `docs/api/` 之下，文档优先级随 `docs/api/`（高于 PROJECT_REQUIREMENTS）。

## 2. 全局约定

| 约定 | 规则 | 依据 |
|---|---|---|
| JSON 字段命名 | `lowerCamelCase`，与客户端 Kotlin 属性名逐字一致 | 本表 |
| 枚举值命名 | `UPPER_SNAKE_CASE` 字符串传输（如 `"S4"`、`"LOCAL_ONLY"`） | 本表 |
| 时间 | 毫秒时间戳，`number`（int64），不用字符串日期 | API 契约原则 3 |
| 时长 | 毫秒，`number`（int64） | 本表 |
| ID | 字符串（如 `"SUBJ-DEMO-0001"`、`"R-001"`），不用自增整数外泄 | 本表 |
| 可空性 | 显式声明；可空字段必须写明置空条件 | API 契约原则 4 |
| 列表 | 统一游标分页 `{ items, nextCursor, hasMore }` | API 契约原则 7 |
| 错误 | `{ code, message, requestId, details? }` | `00-接口通则.md` |

## 3. 对象字段表

### 3.1 Subject（被记录者）

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | string | 否 | 被记录者 ID |
| `nickname` | string | 否 | 昵称（不使用真实姓名） |
| `relation` | string | 否 | 与家属的关系（如"母亲"） |
| `age` | number | 否 | 年龄（整数岁；不采集出生日期） |

### 3.2 DiaryRecord（录音记录）

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | string | 否 | 记录 ID |
| `subjectId` | string | 否 | 归属被记录者 ID（资源归属校验依据） |
| `recordedAt` | number | 否 | 录制完成时间，毫秒时间戳 |
| `durationMillis` | number | 否 | 录音时长（毫秒）；有效范围 10000–300000 |
| `taskType` | enum | 否 | 任务类型，见 3.7 TaskType |
| `recorderRole` | enum | 否 | 录制者角色，见 3.8；代录必须可识别（论文数据） |
| `localAudioPath` | string | 是 | **客户端专用**：音频在设备私有目录的路径，**严禁出现在任何接口的请求/响应中** |
| `syncState` | enum | 否 | 同步状态，见 3.9 |
| `qualityTag` | enum | 否 | 质量标签，见 3.10；用词禁止"合格/不合格" |
| `metrics` | MetricView[] | 否 | 当次指标视图；可为空数组（分析未完成时） |
| `transcript` | string | 是 | ASR 转写文本；**ASR 失败时为 null，不是空串**（原则 4） |
| `familyNote` | string | 是 | 家属备注 |
| `eventTags` | string[] | 否 | 事件标注；取值来自预设项（感冒/失眠/情绪低落/住院/旅行/家庭事件）或家属自定义 |

### 3.3 MetricView（指标视图）

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `kind` | enum | 否 | 指标种类，见 3.6 |
| `direction` | enum | 否 | 偏离方向，见 3.6 |
| `statusLabel` | string | 否 | 服务端下发的展示标签（"稳定"/"有变化"/"数据不足"），客户端只渲染不拼接 |
| `hasEnoughData` | boolean | 否 | 数据是否足够建趋势；false 时前端渲染虚线占位 |
| `miniTrend` | number[] | 否 | 归一化迷你走势（0–1 相对值），**不含真实量纲** |
| `value` | number | 是 | **仅存在于 API-03 响应**（契约原则 2：返回原始数值但不暴露统计量）。客户端 `MetricView` 类型**刻意不设此字段**——用类型层面杜绝展示原始数值 |

### 3.4 StatusView（状态机视图）

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `statusCode` | enum | 否 | 状态机当前值，见 3.5；**只在服务端计算** |
| `copyKey` | string | 否 | 服务端文案 key（`status.s0`…`status.s6`），客户端按 key 取文案 |
| `validRecordCount` | number | 否 | 有效记录数（充分度条用） |
| `nonDiseaseExplanation` | string | **条件必填** | **S4/S5 时必须非空**；为空时服务端应返回 500，客户端 StatusBanner 渲染到空值直接抛异常 |
| `changedMetricCount` | number | 否 | S4/S5 文案中"有 N 项变化"的 N；非 S4/S5 为 0 |
| `changedMetricNames` | string | 否 | S4/S5 变化指标名列表（顿号分隔）；非 S4/S5 为空串 |
| `actionRoute` | string | 是 | 行动入口路由；仅 S5 为 `"family/records"`（回看原始记录，2026-09-28 B3：原 `family/visit_prep` 就医准备页已移除），其余 null |

### 3.5 枚举字典

| 枚举 | 取值 | 说明 |
|---|---|---|
| `StatusCode` | `S0` 未开始 ｜ `S1` 基线建立中 ｜ `S2` 稳定 ｜ `S3` 数据不足 ｜ `S4` 需要关注 ｜ `S5` 建议就医评估 ｜ `S6` 已就医 | 状态机只在服务端计算 |
| `MetricKind` | `SPEECH_RATE` 说话速度 ｜ `PAUSE` 说话流畅度 ｜ `VOCAB` 用词丰富程度 ｜ `COHERENCE` 说话的连贯性 | 固定 4 项；**2026-09-28 对齐后端 `metrics.metric_key`**（原 FLUENCY/LEXICAL 更名），见 `../backend/schema.md` |
| `MetricDirection` | `LOWER` ｜ `SAME` ｜ `HIGHER` ｜ `UNKNOWN` | 只有方向，没有幅度 |
| `TaskType` | `DAILY_FREE` 每日叙述 ｜ `WEEKLY_PICTURE` 每周图片描述 ｜ `WEEKLY_FLUENCY` 每周语义流畅性 ｜ `WEEKLY_FREE` 每周自由叙述 | 一期 4 种（2026-09-28 补齐 WEEKLY_FREE，对齐 API-02） |
| `RecorderRole` | `ELDER_SESSION` 老人端会话自录 ｜ `FAMILY_PROXY` 家属端代录 | 代录必须可识别；2026-09-28 更名（老人无账号） |
| `SyncState` | `LOCAL_ONLY` ｜ `UPLOADING` ｜ `UPLOADED` ｜ `FAILED` | 上传失败只在家属端呈现 |
| `QualityTag` | `NORMAL` ｜ `NOISY` ｜ `TOO_SHORT` ｜ `TOO_MUCH_SILENCE` ｜ `NO_TRANSCRIPT` | 用词禁止"合格/不合格" |
| `UserMode` | `ELDER` ｜ `FAMILY` | 端内模式；不随接口传输 |

## 4. 字段归属边界

| 类别 | 字段 | 规则 |
|---|---|---|
| **客户端专用**（严禁进接口） | `localAudioPath`、偏好设置（SharedPreferences 的全部 key） | 只存在于端内存储 |
| **服务端专用**（客户端模型不承载） | `value`（指标原始数值）、基线带、均值等统计量 | 见 `API-03`；客户端按类型设计隔离 |
| **双向传输** | 上表 3.1–3.4 的其余字段 | 前后端逐字一致 |

## 5. 禁止字段清单（合规红线，见 AGENTS.md 第 6 节）

以下字段**不允许出现在任何接口响应、任何客户端模型、任何日志中**：

`zScore`、`mean`、`stdDev`、`probability`、`confidence`、`riskLevel`、`score`（量表分数仅限研究模式域 `API-06`）、`diagnosis`、`screeningResult`

新增字段若语义落在"概率/评分/风险分级/诊断"内，一律拒绝设计——先回合规边界讨论。

## 6. 字段变更流程

```
1. 改本表（新增行或修改行，写明类型/可空/置空条件）
2. 改客户端 Models.kt（保持逐字一致）
3. 改对应 docs/api/API-0x-*.md 的请求/响应体小节
4. 后端就绪后由后端更新 OpenAPI（CI 校验一致性）
5. 破坏性变更（删字段、改类型、收窄可空性）→ 升 /v2，旧版保留 ≥1 个迭代周期
```

## 7. 联调一致性核对清单（每次联调前过一遍）

- [ ] 字段名逐字一致（含大小写）
- [ ] 类型一致（string/number/boolean/数组/对象）
- [ ] 可空性一致（可空字段客户端有 null 分支处理）
- [ ] 枚举值集合一致（服务端新增枚举值时客户端必须有 UNKNOWN/兜底分支）
- [ ] 时间戳为毫秒 int64
- [ ] 列表走游标分页
- [ ] 本表、Models.kt、API-0x、OpenAPI 四处无分叉
