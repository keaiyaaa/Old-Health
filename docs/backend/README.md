## 4. 服务边界

一期是**单体 API 服务 + 一个 Worker**，不做微服务。

```
gateway  →  api（单体）  →  postgres
                     ↘    →  redis（队列 + 缓存）
worker   ←  redis 队列
         →  对象存储（境内）
         →  境内 ASR
```

**为什么不做微服务**：用户量、团队规模、迭代速度都不支撑。模块边界在**代码包**上体现，不在进程上体现。等某个模块真的需要独立扩缩容时再拆。

**禁止事项**：不为"未来可能"预建微服务、消息总线、服务网格。

## 5. 跨模块通用约定

### 5.1 分层

| 层 | 职责 | 禁止 |
|---|---|---|
| Controller / 路由 | 协议适配、参数校验、鉴权 | **不写业务逻辑** |
| Application Service | 用例编排、事务边界、幂等 | 不直接拼 SQL |
| Domain | 领域对象、状态机、业务规则 | 不依赖框架与 IO |
| Repository | 持久化 | 不写业务规则 |
| Infrastructure | 对象存储、ASR、队列、缓存 | 不被 Domain 直接依赖（走接口） |

### 5.2 鉴权与资源归属（每个接口都要过）

**三道检查，缺一不可**：

1. **认证** —— 令牌有效且未过期
2. **角色** —— 角色具备该操作权限（见 `../PROJECT_REQUIREMENTS.md` 2.4）
3. **资源归属** —— 请求的资源确实属于该账号可访问的范围

**越权一律返回 404，不返回 403**（防资源存在性探测）。

**实现要求**：资源归属校验必须写成**统一的中间件/守卫**，不允许每个接口手写一遍。手写必然有漏。

### 5.3 幂等

| 场景 | 幂等键 |
|---|---|
| 音频上传登记 | `Idempotency-Key`（客户端生成，记录级唯一） |
| 触发分析 | 由 `recordId` 天然幂等（同一记录只分析一次） |
| 删除操作 | 天然幂等（删已删的返回成功） |
| 注销 | 天然幂等 |

**要求**：幂等键需在服务端存储并校验，重复请求返回**首次的结果**，不重复执行副作用。

### 5.4 事务边界

| 操作 | 事务范围 |
|---|---|
| 登记记录 | 记录 + 元数据 + 入队任务（**入队必须在事务内或用事务性发件箱**） |
| 写入分析结果 | 指标 + 记录状态 + 状态机重算（同一事务） |
| 删除记录 | 标记删除 + 入队清理任务 |
| 注销 | 标记注销 + 入队清理任务 |

**禁止**：在事务内做网络调用（ASR、对象存储）。网络调用必须在事务外，用队列解耦。

### 5.5 队列与重试

| 队列 | 任务 | 重试策略 |
|---|---|---|
| `analysis` | ASR + 文本指标计算 | 最多 3 次，指数退避；ASR 超时错误可重试，参数错误不重试 |
| `cleanup` | 音频删除、到期清理 | 最多 5 次，退避；失败进死信队列并告警 |
| `notify` | 家属端推送 | 最多 3 次 |

**死信队列**：所有队列必须有死信队列，且死信积压必须告警。**不允许"重试到成功为止"** —— 那会把队列堵死。

### 5.6 缓存

| 用途 | 键 | TTL |
|---|---|---|
| 状态机结果 | `status:{subjectId}` | 5 分钟 |
| 基线 | `baseline:{subjectId}` | 5 分钟 |
| 权限判定 | `perm:{accountId}:{subjectId}` | 1 分钟（短，避免撤权延迟） |
| 签名 URL | 不缓存 | — |

**硬规则**：**权限判定缓存必须有撤权失效机制**。绑定解除时主动删除缓存，否则会出现"已解绑但还能看"的事故。

### 5.7 审计

**必须审计的操作**（写入 `AuditLog`，保留 12 个月）：

- 读取音频（谁、何时、哪条）
- 导出数据集（含全量导出与就诊摘要）
- 同意变更（授予 / 撤回）
- 权限变更（绑定 / 解绑 / 改角色）
- 删除与注销
- 管理员访问任何用户数据

**禁止记录**：音频内容、转写全文、手机号明文、令牌、密钥。

### 5.8 异常与错误模型

统一错误结构见 `../api/00-接口通则.md`。后端实现要求：

1. 错误码为**稳定枚举**，不随文案变化
2. 面向用户的 `message` 与面向开发的 `detail` 分离
3. 内部异常**不泄露堆栈**到响应
4. 每个响应带 `requestId`，与日志关联

### 5.9 日志

| 允许 | 禁止 |
|---|---|
| requestId、接口、耗时、状态码 | 音频、转写全文 |
| 状态流转（subjectId、from、to） | 手机号明文（需脱敏） |
| 队列任务 ID、重试次数 | 令牌、Cookie、密钥 |
| 错误类型与脱敏堆栈 | 请求体原文（可能含转写） |

## 8. 工程实现选型补充（FastAPI 落地，2026-09-28）

技术栈定下来后，把"栈无关设计"落成"栈相关决定"，避免编码时现场拍板：

### 8.1 数据库与迁移

- ORM：**SQLAlchemy 2.0** + **Alembic** 迁移；schema 随模块联动修改完成后统一定稿（第 1 节"数据库表结构待设计"即指此项）
- 迁移纪律：每次 schema 变更必须有 Alembic revision，**禁止手改线上库**

### 8.2 Celery 实现要求

| 要求 | 实现 |
|---|---|
| 任务幂等 | 以 `recordId` 为幂等键：**指标表 `recordId` 唯一约束兜底** + 任务开始前 Redis 分布式锁（`lock:analysis:{recordId}`，TTL = 任务超时）双保险 |
| 事务性发件箱 | PG `outbox` 表；**Celery beat 启动的发布者任务**轮询 outbox 投递到队列（禁止业务事务内直接调 `task.delay`） |
| 重试 | `autoretry_for` + `retry_backoff`；不可重试异常显式抛出，不自动重试 |
| 死信 | 重试耗尽进死信队列 + 告警（已有设计，实现层用 Celery `on_failure` 钩子落库并通知） |
| 并发 | worker 并发数按 ASR 配额设定，`worker_concurrency` 上限写死在配置 |

### 8.3 定时任务（统一走 Celery beat，不另引 crontab）

| 任务 | 频率 | 对应设计 |
|---|---|---|
| `dailySweep` | 每日 | 状态降级检查、到期清理提醒（基线与状态机 7） |
| 到期清理扫描 | 每日 | 留存期到期记录 → `DeletionTask`（数据生命周期 4.1 应用层） |
| 导出产物过期清理 | 每小时 | 24 小时产物删除（数据生命周期 3.3） |
| outbox 发布者 | 每秒 | 事务性发件箱投递（8.2） |
| 依从性统计预计算 | 每日 | 研究数据管理 6 |

### 8.4 ASR 厂商抽象层（C3 未定，先定接口）

```
ASRProvider（抽象接口，worker 内依赖注入）
├── submit(audio_path, dialect) → task_ref
├── poll(task_ref) → state
├── fetch_result(task_ref) → AsrResult
└── is_retryable(error) → bool
```

C3 选型定了只换 adapter 实现，流水线代码不动。`asrEngine` / `asrModelVersion` 字段记录实际使用的引擎，口径可追溯。

### 8.5 邮件验证码通道

- **不用 QQ 邮箱个人 SMTP 发信**（额度小、易进垃圾箱、不稳定）
- 用**阿里云邮件推送 / 腾讯云 SES 类服务**发信；QQ 邮箱只是用户收件端
- 发信模板含验证码、有效期、"非本人操作请忽略"；发送在事务外（已有设计）

### 8.6 会话与令牌

- access token：JWT（≤30 分钟），无状态
- refresh token：**有状态**，存 PG `sessions` 表（含 device_id、client 类型、最后活跃时间）——多设备踢出、密码重置后全端吊销都靠它，**不用纯无状态 JWT**
- 令牌吊销：改密码 / 注销申请时按 accountId 删 sessions；单设备登出删单条

### 8.7 部署形态（一期）

```
docker-compose：nginx(gateway) + api(FastAPI/uvicorn) + worker(Celery)
                + postgres + redis + 对象存储（云厂商，不在 compose 内）
```

配置全部走环境变量；**客户端构建产物不得含任何服务端密钥**（AGENTS.md 红线）。
