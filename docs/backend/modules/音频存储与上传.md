# 后端模块：音频存储与上传

**覆盖需求**：FR-1、FR-6.1、FR-6.5
**对应接口**：`../../api/API-02-录音与上传.md`

---

## 1. 职责边界

### 1.1 职责

签发预签名上传地址、接收记录登记、管理音频对象的生命周期、向客户端提供短时效播放地址。

### 1.2 不做什么

| 不做 | 理由 |
|---|---|
| **不经手音频二进制** | 音频走预签名 URL 直传对象存储，业务服务器不中转（降低合规压力与带宽成本） |
| 不做音频转码（一期） | 客户端已按固定参数录制，无需服务端转码 |
| 不做音频内容分析 | 那是分析流水线的事 |
| 不做音频公开访问 | 对象一律私有 |
| 不做长期有效的播放 URL | 签名 ≤15 分钟 |

## 2. 领域对象

```
AudioObject
├── objectKey           # {subjectId}/{yyyy}/{mm}/{uuid}.m4a
├── subjectId
├── recordId
├── sizeBytes
├── sha256              # 上传时校验
├── contentType
├── durationSec
├── sampleRate
├── uploadedAt
├── storageClass        # STANDARD | ARCHIVE（长期留存可转归档）
└── deletedAt           # 非空即已删除

UploadSession           # 预签名会话
├── sessionId
├── subjectId
├── objectKey
├── signedUrl
├── expiresAt           # ≤15 分钟
└── consumedAt          # 单次使用标记

Record
├── recordId
├── subjectId
├── recorderRole        # ELDER_SESSION | FAMILY_PROXY
│                       # 2026-09-28：一期两者都启用——老人端会话自录 + 家属端代录（FR-1.5 升为一等能力）
├── taskType            # DAILY_FREE | WEEKLY_PICTURE | WEEKLY_FLUENCY | WEEKLY_FREE
├── scheduledAt / actualStartedAt / durationSec
├── syncState           # LOCAL_ONLY | UPLOADING | SYNCED | FAILED
├── qualityFlag         # VALID | SUSPECT | INVALID
└── analysisState       # PENDING | ANALYZING | DONE | FAILED
```

**注意 `recorderRole`**：论文取数时必须能区分老人自录与家属代录，这是数据可用性的前提。**由服务端按会话类型判定**（老人端会话 = ELDER_SESSION，家属端 = FAMILY_PROXY），客户端声明不可信（2026-09-28 决策：家属端可以录音）。

> **⚠️ 2026-09-28 变更（C5）**：登记接口**不再接收声学指标**（`acousticMetrics` / `snrDb` / `silenceRatio` / `clientQualityFlag` 全部删除）。声学指标由云端 worker 统一计算，见 `分析流水线.md` 第 4 节。

## 3. 状态机

### 3.1 记录同步状态

```
LOCAL_ONLY ──上传成功──▶ SYNCED
     │                      ▲
     └──上传中──▶ UPLOADING ─┘
                    │
                    └──重试耗尽──▶ FAILED ──手动重试──▶ UPLOADING
```

**客户端与服务端的职责分工**：`LOCAL_ONLY` / `UPLOADING` / `FAILED` 由**客户端**维护；服务端只在收到登记请求后创建 `SYNCED` 记录。**服务端不感知本地未上传的记录**，这是离线优先架构的必然结果。

### 3.2 分析状态

```
PENDING ──▶ ANALYZING ──▶ DONE
                │
                └──失败──▶ FAILED（可重试，有限次）
```

## 4. 权限

| 操作 | 校验 |
|---|---|
| 获取上传地址 | `canWrite(accountId, subjectId)` + `SENSITIVE` 同意有效 |
| 登记记录 | 同上 |
| 获取播放地址 | `canAccess(accountId, subjectId)` + `SENSITIVE` 同意有效 |
| 删除记录 | `canWrite` 或被记录者本人（见 `../../PROJECT_REQUIREMENTS.md` 2.5） |
| 运营管理员 | **无任何音频访问权限** |

**关键：所有音频相关接口都必须校验 `SENSITIVE` 同意有效。** 撤回同意后，即使绑定关系还在，也不能再访问音频。

## 5. 上传流程

```
1. 客户端请求上传地址
   POST /v1/records/upload-url
   → 服务端校验权限与同意
   → 生成 objectKey（服务端生成，不接受客户端指定）
   → 签发预签名 URL（≤15 分钟，单对象绑定）
   → 返回 { sessionId, objectKey, signedUrl, expiresAt }

2. 客户端直传对象存储
   PUT {signedUrl}  （不经业务服务器）

3. 客户端登记
   POST /v1/records
   Header: Idempotency-Key
   Body: { sessionId, objectKey, sha256, durationSec, recorderRole, taskType, ... }
   → 服务端校验 objectKey 属于该 sessionId
   → 校验对象确实存在且 sha256 匹配
   → 创建 Record（syncState = SYNCED）
   → 事务内入队 analysis 任务（worker 内算声学 + ASR + 文本指标）
   → 返回 { recordId }

4. 客户端轮询分析状态
   GET /v1/records/{id}/status
```

### 5.1 为什么 objectKey 由服务端生成

如果允许客户端指定 objectKey，攻击者可以：
- 覆盖他人的对象（路径穿越）
- 构造可预测的键名去猜别人的音频

服务端生成 + 强制路径前缀 `{subjectId}/`，并在登记时校验 `objectKey` 与 `sessionId` 的绑定关系。

### 5.2 预签名 URL 的安全要求

| 要求 | 说明 |
|---|---|
| 短时效 | ≤15 分钟 |
| 单对象绑定 | 一个签名只能写一个 key |
| 单次使用 | 服务端记录 `consumedAt`，登记时校验 |
| 限定方法 | 只允许 PUT（上传）或 GET（播放），不给 DELETE |
| 限定大小 | 签名时带 `Content-Length` 上限（≤10MB） |

## 6. 上传安全校验（对照 `../../PROJECT_REQUIREMENTS.md` 9.5）

| 校验 | 实现 |
|---|---|
| 扩展名 | 只接受 `.m4a` / `.aac` / `.wav` |
| MIME | 只接受 `audio/*` |
| **文件签名** | 读取文件头魔数校验（不信任扩展名与 MIME 声明） |
| 大小 | ≤10MB；超出拒绝 |
| 数量配额 | 单账号日上传条数上限；总存储配额 |
| SHA-256 | 客户端上传时提供，服务端下载校验（或对象存储事件触发校验） |
| 压缩炸弹 | 音频不解压，天然规避；若引入压缩包必须限制解压比 |
| 可执行内容 | **不执行任何用户上传内容**；音频只被 ASR 读取，不被执行 |

### 6.1 校验时机

**魔数校验在客户端做一次（快速失败），服务端必须再做一次（不可信客户端）。** 服务端校验通过对象存储事件或首次读取时执行。

## 7. 事务与幂等

| 操作 | 事务 | 幂等 |
|---|---|---|
| 获取上传地址 | 无事务（只签发） | 不幂等（每次新 session，可多次签发） |
| 登记记录 | Record + 入队（事务性发件箱） | **`Idempotency-Key` 强制**，重复请求返回首次 `recordId` |
| 删除记录 | 标记删除 + 入队 cleanup | 天然幂等 |

**登记接口的幂等是刚需**：客户端在弱网下会重试，如果每次重试都创建一条新记录，用户会看到重复记录，论文数据会被污染。

**实现**：`Idempotency-Key` 存服务端（TTL 24 小时），重复请求直接返回缓存的响应体。

---

## 8. 队列

| 队列 | 任务 | 触发 |
|---|---|---|
| `analysis` | ASR + 指标计算 | 登记记录后（事务内入队） |
| `cleanup` | 删除音频对象、到期清理 | 删除请求、定时任务 |

**事务性发件箱**：入队必须在数据库事务内写入 outbox 表，由独立的发布者消费 outbox 投递到队列。**禁止在事务内直接调队列 API**（事务回滚会导致任务丢失或重复）。

---

## 9. 缓存

| 键 | 内容 | TTL |
|---|---|---|
| `uploadSession:{sessionId}` | 会话与 objectKey 绑定关系 | 15 分钟 |
| `record:{recordId}` | 记录元数据 | 5 分钟 |
| 签名 URL | **不缓存** | — |

---

## 10. 审计

必须记录：

- 音频读取（谁、何时、哪条 recordId）—— **每次生成播放签名都留痕**
- 上传登记（recordId、subjectId、recorderRole、大小）
- 删除（操作者、recordId、原因）
- 配额超限拒绝

**禁止记录**：签名 URL 全文（等价于凭证）、音频内容。

---

## 11. 异常处理

| 异常 | 响应 |
|---|---|
| 权限不足 / 资源不存在 | 404 |
| 未授予敏感信息同意 | 403 + `CONSENT_REQUIRED` |
| 签名过期 | 400 + `URL_EXPIRED`，前端重新获取 |
| objectKey 与 session 不匹配 | 400 + `INVALID_OBJECT_KEY`（**不透露详情**） |
| 对象不存在 | 400 + `OBJECT_NOT_FOUND` |
| sha256 不匹配 | 400 + `CHECKSUM_MISMATCH` |
| 文件过大 / 类型不符 | 400 + `INVALID_FILE` |
| 配额超限 | 429 + `QUOTA_EXCEEDED` |
| 对象存储不可用 | 503 + 可重试；不暴露上游细节 |

## 12. 安全

| # | 要求 |
|---|---|
| 1 | 对象存储桶**私有**，禁止任何公开读 |
| 2 | 签名 URL 短时效 + 单对象 + 单次使用 |
| 3 | objectKey 服务端生成，含 `subjectId` 前缀，登记时校验绑定 |
| 4 | 上传大小上限在签名时就带上，不只在业务层校验 |
| 5 | 魔数校验服务端必做 |
| 6 | 音频对象存储**服务端加密**（SSE） |
| 7 | 传输 TLS 1.2+ |
| 8 | 运营管理员无访问权限（数据层） |
| 9 | 删除必须删对象本体，不只是标记 |
| 10 | 对象存储出站/入站白名单，禁止跨境 |

## 14. 验收标准

- [ ] 音频**不经业务服务器**，走预签名直传（`../../PROJECT_REQUIREMENTS.md` 10.6）
- [ ] 签名 URL ≤15 分钟、单对象绑定、单次使用
- [ ] objectKey 服务端生成，含 `subjectId` 前缀
- [ ] 登记接口 `Idempotency-Key` 幂等，并发重试只创建 1 条（E2E-02）
- [ ] 服务端做魔数校验，不信任扩展名与 MIME（SEC-05）
- [ ] 单文件 ≤10MB，超限拒绝
- [ ] 对象存储桶私有，无公开读
- [ ] 音频对象服务端加密
- [ ] 所有音频接口校验 `SENSITIVE` 同意有效
- [ ] 运营管理员无音频访问权限（数据层验证）
- [ ] 每次生成播放签名都有审计记录
- [ ] 删除为硬删除，对象本体确实消失（E2E-08）
- [ ] `recorderRole` 正确区分自录与代录
- [ ] 日志中不含签名 URL 全文
- [ ] 断网时录音功能不降级（客户端侧，见前端模块）
