# 后端模块：研究数据管理

**覆盖需求**：FR-8
**对应接口**：`../../api/API-06-研究模式.md`
**默认状态**：关闭

---

## 1. 职责边界

### 1.1 职责

为论文提供匿名化、可导出、可追溯的数据集管理：受试者匿名映射、临床量表存储、结构化任务协议下发、依从性统计、数据集导出。

### 1.2 不做什么

| 不做 | 理由 |
|---|---|
| **不做模型推理** | 模型在论文侧离线跑，服务端不跑 AD 分类 |
| **不做量表自动评分** | 量表由人评估，服务端只存储 |
| **不做标注工具** | 标注在电脑侧做，服务端只提供数据 |
| **不做真实姓名与匿名 ID 的自动暴露** | 映射关系单独授权，且不可批量导出 |
| 不做多中心权限体系（一期） | 单研究者场景，不预建 |
| 不做研究数据与产品数据的物理隔离库 | 同库字段隔离，一期规模不需要双库 |

### 1.3 最重要的一条边界

**研究模块绝不能向 C 端泄露任何数据。** 具体说：

- 研究模式下录入的 MMSE / MoCA 分数，**C 端任何接口都不可返回**（X-2）
- 研究模式的开关状态，不影响 C 端的任何呈现
- 研究数据的存在，不改变 C 端的基线、状态、趋势计算

**验证方式**：关闭研究模式后，C 端的全部接口响应应与"从未开启过研究模式"完全一致。

```

├── revokedAt
└── evidenceRef

ClinicalScale
├── scaleId

TaskProtocol
├── protocolId
├── weekIndex
├── taskType            # WEEKLY_PICTURE | WEEKLY_FLUENCY | WEEKLY_FREE
```

**`TaskProtocol.version` 是刚需**：指导语改动会让前后数据不可比，必须能追溯每个样本用的是哪一版。

## 3. 状态机

### 3.1 受试者

```
ENROLLED ──撤回研究同意──▶ WITHDRAWN
```

撤回后：停止采集研究数据；已导出的匿名数据集按伦理承诺处理（**不可追溯撤回**，这一点必须在知情同意中说清楚）。

### 3.2 研究同意

与产品同意**独立**。撤回研究同意**不影响**产品功能，只是停止研究数据使用。

> **⚠️ 2026-09-28 与新 Consent 规则的关系（决策 #18 + 挂账号）**：
> 产品侧 Consent 已统一挂账号（见 `账号与身份.md` 2.2）。本模块的 `ResearchConsent` 是**研究域内部对象**，仍挂 `researchSubjectId`——这是刻意保留的两套体系：
>
> | | 产品 Consent | 研究域 ResearchConsent |
> |---|---|---|
> | 挂载 | 账号 | 匿名受试者 |
> | 授予/撤回者 | 账号本人 | 受试者本人或研究者 |
> | 影响 | 控制产品功能与数据访问 | 只控制研究数据的采集与导出 |
>
> **边界规则**：两边互不读写对方的状态；`RESEARCH` 类型的产品 Consent 与 `ResearchConsent` 必须同时有效才可导出研究数据集（双闸门）。

## 4. 权限

| 操作 | 校验 |
|---|---|
| 访问研究模式 | 账号角色 = `RESEARCHER` + 研究模式开关开启 |
| 录入量表 | `RESEARCHER` + 项目 `ACTIVE` |
| 查看受试者列表 | `RESEARCHER`；**只返回匿名 ID** |
| 导出数据集 | `RESEARCHER` + 受试者研究同意有效 |
| 查看真实姓名映射 | **单独授权**，默认无接口 |
| 撤回研究同意 | 受试者本人或研究者（作为研究方） |

**匿名化实现要求**：

1. 所有面向研究者的接口只接受与返回 `researchSubjectId`
2. 真实姓名映射表**只被内部服务访问**，不暴露 HTTP 接口
3. 导出文件中不出现 `subjectId`、姓名、手机号、精确生日

## 5. 事务与幂等

| 操作 | 事务 | 幂等 |
|---|---|---|
| 受试者入组 | 受试者 + 研究同意 + 匿名 ID 分配 | 同一 subjectId 重复入组返回已有 |
| 量表录入 | 量表 + 审计 | 需 `Idempotency-Key`（防重复录入） |
| 撤回同意 | 状态 + 审计 | 天然幂等 |
| 导出 | 创建任务 | 需 `Idempotency-Key` |

**匿名 ID 分配必须事务内完成**，否则并发入组会产生重复编号。

## 6. 队列

| 队列 | 任务 | 说明 |
|---|---|---|
| `export` | 数据集打包 | 与产品导出共用队列，但**优先级更低**（不阻塞用户操作） |
| `adherence` | 依从性统计（定时每日） | 预计算，避免导出时实时算 |

---

## 7. 缓存

| 键 | TTL | 说明 |
|---|---|---|
| 依从性统计 | 1 小时 | 预计算结果 |
| 任务协议 | 长期（版本化） | 变更必须升版本 |
| 受试者列表 | 5 分钟 | 入组/撤回时失效 |

---

## 8. 审计

| 事件 | 记录 |
|---|---|
| 受试者入组 / 撤回 | researchSubjectId、时间、操作者 |
| 量表录入 | researchSubjectId、量表类型、时间、操作者（**不记录分数值**） |
| 数据集导出 | 项目、范围、时间、操作者 |
| 真实姓名映射访问 | **必填目的**，最高级别审计 |

**量表分数不进日志**：它是敏感医疗信息，且日志的留存与访问控制弱于数据库。

---

## 9. 异常处理

| 异常 | 处理 |
|---|---|
| 研究模式未开启 | 404（路由不存在，不暴露功能存在性） |
| 非研究者访问 | 404 |
| 项目已关闭 | 403 + `PROJECT_CLOSED`（需明确告知） |
| 研究同意已撤回 | 拒绝导出该受试者数据，明确说明 |
| 量表未录入 | 依从性统计中标记缺失，不报错 |
| 导出体积过大 | 提示分批（按受试者或时间范围） |
| 音频部分缺失 | 导出清单标注缺失条数，不静默跳过 |

---

## 10. 安全

| # | 要求 |
|---|---|
| 1 | 匿名化：导出文件中无姓名、手机号、精确生日、内部 subjectId |
| 2 | 真实姓名映射无 HTTP 接口，仅内部服务可访问 |
| 3 | 研究数据与产品数据**在接口层严格隔离** |
| 4 | C 端接口**永不返回**量表分数（X-2） |
| 5 | 撤回研究同意后，该受试者数据立即不可导出 |
| 6 | 量表分数不进日志 |
| 7 | 导出产物 24 小时必删（同产品导出） |
| 8 | 研究模式关闭时路由不存在 |
| 9 | 研究数据境内存储，不出境 |

## 11. 测试

| 类型 | 覆盖 |
|---|---|
| 单元 | 匿名 ID 生成唯一性、任务协议版本推进、依从性计算 |
| **隔离测试** | 研究模式开启 vs 关闭，断言 C 端全部接口响应**完全一致** |
| **匿名化测试** | 全量导出文件中扫描姓名 / 手机号 / 内部 subjectId，命中数为 0 |
| **红线测试** | 断言 C 端任何接口不返回 `mocaB` / `mmse` / `fluencyScore`（E2E-11） |
| 撤回测试 | 撤回研究同意后断言导出被拒 |
| 并发测试 | 同一 subjectId 并发入组，断言只分配一个匿名 ID |
| 一致性测试 | 任务指导语跨版本对比，变更必须伴随版本号变化 |
| 边界 | 0 受试者 / 单受试者 1000 条 / 全部缺量表 |

## 12. 验收标准

- [ ] 研究模式**默认关闭**，关闭时路由不存在（FR-8.1）
- [ ] 研究知情同意与产品同意**分离**，可单独撤回（FR-8.1）
- [ ] 界面与导出文件中**无真实姓名**，只有匿名 ID（FR-8.2）
- [ ] 真实姓名映射**无 HTTP 接口**，仅内部服务可访问
- [ ] 量表录入记录分数、日期、评估人（FR-8.3）
- [ ] 量表分数**不进日志**
- [ ] 任务指导语逐字固定且**版本化**，跨被试一致（FR-8.4）
- [ ] 依从性报表含完成率、缺失分布、**代录占比**（FR-8.5）
- [ ] 数据集导出字段与论文数据字典一致（FR-8.6）
- [ ] 支持人工转录导入，与 ASR 文本并存（FR-8.7）
- [ ] 导出文件不含 `subjectId`、姓名、手机号、精确生日
- [ ] **C 端任何接口不返回量表分数**（E2E-11）
- [ ] 研究模式开关**不影响 C 端任何呈现**（隔离测试通过）
- [ ] 撤回研究同意后数据立即不可导出
- [ ] 导出产物 24 小时必删
- [ ] 匿名 ID 分配事务内完成，并发安全
- [ ] 研究数据境内存储（SEC-12）

> ⚠️ 若使用自采数据，必须有伦理批件（IRB）。见 `../../planning/待确认事项.md` C4。
