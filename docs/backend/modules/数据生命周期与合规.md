# 后端模块：数据生命周期与合规

**覆盖需求**：FR-6.3、FR-6.6、FR-7、NFR-1
**对应接口**：`../../api/API-05-导出与注销.md`

> **⚠️ 2026-09-28 变更（B3）**：**就诊摘要功能整体移除**——服务端与客户端都不再生成任何面向医生的输出。
> 产品定位收紧为"只记录趋势与话语变化，不给判断"。全量导出（`FULL` / `METRICS_ONLY`）保留。
> 另（决策 #18）：注销后老人数据的处置按绑定关系判定（见 5.3）。

---

## 1. 职责边界

### 1.1 职责

管理数据的**全生命周期**：留存期限、到期清理、单条删除、全量清空、账号注销、数据导出。以及支撑合规所需的审计与同意联动。

**这是全项目合规风险最集中的后端模块。** 它决定了"用户能不能真的删掉自己的数据"——这个问题的答案，比任何功能都重要。

### 1.2 不做什么

| 不做 | 理由 |
|---|---|
| **不做软删除作为终态** | 用户看到的"已删除"必须是真删除 |
| **不做"数据保留以便改进服务"** | X-15；注销即彻底删除 |
| 不做数据变现、不做第三方共享 | X-15 |
| 不做跨境的备份或灾备 | X-14 |
| **不生成面向医生的临床判断文件** | 见 6.2 与 `../../PROJECT_REQUIREMENTS.md` 9.2.4 |
| 不做数据恢复服务 | 删除不可逆，这是设计而非缺陷 |

## 3. 状态机

### 3.1 删除任务

```
PENDING ──▶ RUNNING ──成功──▶ DONE
                │
                └──失败──▶ FAILED ──重试──▶ RUNNING（最多 5 次）
                              │
                              └──耗尽──▶ DEAD（告警 + 人工介入）
```

**死信必须告警。** 删除失败而不告警，等于用户以为删了但没删——这是最严重的合规事故类型。

### 3.2 账号注销

```
ACTIVE ──申请──▶ DELETING ──7 天──▶ PURGING ──▶ DELETED
                    │
                    └──冷静期内登录并撤销──▶ ACTIVE
```

| 状态 | 数据可见性 | 数据可访问性 |
|---|---|---|
| `DELETING` | 仅本人可见"注销中"提示 | 本人可撤销；其他人不可见 |
| `PURGING` | 不可见 | 不可访问 |
| `DELETED` | 不可见 | 已硬删除 |

### 3.3 导出任务

```
PENDING ──▶ GENERATING ──▶ READY ──24 小时──▶ EXPIRED（产物删除）
```

**导出产物必须在 24 小时后删除。** 否则对象存储里会堆积大量包含音频的数据包，是重大合规风险。

## 4. 保留期限与到期清理（FR-6.6）

| 数据 | 默认 | 可调 | 到期行为 |
|---|---|---|---|
| 音频文件 | 24 个月 | 6 / 12 / 24 / 永久 | 硬删除 |
| 转写文本与指标 | 与音频同期 | 否 | 随音频删除 |
| 基线 | 持续 | 否 | 随账号 |
| 状态快照 | 24 个月 | 否 | 硬删除 |
| 审计日志 | 12 个月 | 否 | 硬删除 |
| 导出产物 | 24 小时 | 否 | 硬删除 |
| 临床量表 | 研究项目存续期 | 否 | 按伦理承诺处理 |

### 4.1 三层清理机制（都要有）

| 层 | 机制 | 作用 |
|---|---|---|
| 1. 应用层 | 定时任务扫描到期记录，创建 `DeletionTask` | 主路径 |
| 2. 对象存储层 | 生命周期规则（按前缀日期自动过期） | 兜底，防应用层漏删 |
| 3. 数据库层 | 定时清理已标记删除的行 | 兜底，防残留 |

**为什么需要三层**：应用层可能因为故障、bug、部署中断而漏删。对象存储的生命周期规则是**由存储侧保证的**，不依赖应用正确性。这是最后一道防线。

### 4.2 备份中的副本

备份中的副本**无法被单条删除**。处理方式：

1. 备份轮转周期 ≤30 天，副本随轮转自然过期
2. **必须在隐私政策中明确说明这一点**，不能装作没有
3. 注销时记录 `purgeRequestedAt`，备份恢复演练时必须能识别并跳过已删除数据

**这是"数据能不能真的删干净"的诚实回答。** 不写清楚才是风险。

## 5. 删除流程

### 5.1 单条删除（FR-6.3）

```
1. 校验权限（canWrite 或本人）
2. 事务内：标记 Record.deletedAt + 创建 DeletionTask + 写审计
3. 事务外：cleanup 队列执行
     ├─ 删除对象存储中的音频
     ├─ 硬删除转写、指标、事件标注
     ├─ 触发基线重算（因为样本数变了）
     └─ 标记 DeletionTask DONE
```

**第 3 步的"触发基线重算"容易漏。** 删掉一条记录后基线不变，会让后续状态判定基于已经不存在的样本。

### 5.2 清空全部记录

仅**老人端会话**可执行（老人设备上、老人在场操作，视为老人本人的意思表示——新模型下老人无账号，以老人端会话替代原"本人"）。删除该 subjectId 下全部记录，**保留账号与绑定关系**。走 5.1 的批量版本。

### 5.3 账号注销

```
1. 校验身份（本人）
2. 标记 Account.status = DELETING，coolingOffUntil = now + 7 天
3. 立即：本地数据清除（客户端侧，见前端模块 8.1）
4. 立即：该账号绑定的所有 CareLink 失效（他人无法再访问）
5. 冷静期内登录 → 提示可撤销
6. 冷静期结束 → PURGING：
     ├─ 硬删除账号、同意、审计关联
     ├─ 对每个曾绑定的 Subject：仍被其他账号绑定 → 数据保留；
     │   无任何有效绑定 → Subject 进入清理，硬删除全部记录与音频（决策 #18）
     └─ 审计日志保留 12 个月（记录"某账号已注销"，不含内容）
7. 标记 DELETED
```

**注意第 6 步的审计日志保留**：审计日志本身记录的是"操作"，不是"内容"。保留它是为了合规可追溯（证明删除确实执行了）。这需要在隐私政策中说明。

## 6. 导出（FR-6.4、FR-7）

### 6.1 导出类型

| 类型 | 内容 | 用途 | 生成位置 |
|---|---|---|---|
| `FULL` 全量导出 | 音频 + 指标 CSV + 标注 + 转写 | 论文取数、换机迁移 | 服务端打包 |
| `METRICS_ONLY` 指标导出 | 指标 CSV | 体积小，便于论文快速取数 | 服务端打包 |

> **就诊摘要（原 `SUMMARY`）已随 B3 决策（2026-09-28）移除**：不再有"给医生看"的任何输出物，客户端本地也不再生成。

### 6.2 服务端与"面向医生的输出"的边界（收紧后）

**服务端不得提供任何"面向医生的结构化临床输出"接口。**

具体地说，不存在这样的接口：
- ❌ `GET /v1/medical/summary`（返回临床判断）
- ❌ `GET /v1/medical/risk`（返回风险分级）
- ❌ 任何返回"建议检查项目"的接口
- ❌ 任何就诊摘要的生成或下载接口（B3 后连客户端本地生成也已移除）

存在的只有：
- ✅ `GET /v1/records`、`GET /v1/metrics/...`、`GET /v1/status/...`（原始数据）

**理由**：只要服务端存在这样的接口，就构成了"给出临床诊断治疗依据和/或建议的决策支持软件"，落入第三类医疗器械。B3 移除就诊摘要后，这条边界从"客户端生成、服务端不碰"进一步收紧为"全链路都不存在此类输出物"。

### 6.3 全量导出

```
1. 校验权限 + 校验同意
2. 创建 ExportJob
3. 异步打包：音频文件 + metrics.csv + events.csv + transcripts/
4. 产物上传到对象存储（私有，独立前缀）
5. 返回短时效下载链接
6. 24 小时后清理产物
7. 审计记录
```

**导出内容不含**：`zScore`、基线均值与标准差、量表分数（除非研究模式且已签研究同意）。

## 7. 权限

| 操作 | 校验 |
|---|---|
| 删除单条 | `canWrite`（任意有效绑定账号，全部审计） |
| 清空全部 | **仅老人端会话**（老人在场，5.2） |
| 注销账号 | 账号本人 |
| 撤回 `PRODUCT` 同意 | 不可撤回（撤回即注销） |
| 撤回 `SENSITIVE` / `ELDER_INFORMED` | **仅老人端会话**（老人本人意思表示） |
| 改留存期限 | 任意有效绑定账号（`canWrite`） |
| 全量导出 | `canAccess` + 同意有效 |
| 查看审计日志 | 账号本人可查看涉及自己的记录；管理员可查全部 |

**硬规则**：删除与撤回同意的"本人"语义在新模型下由**老人端会话**承载（老人设备 + 老人在场 = 老人本人的意思表示，见 `账号与身份.md` 4.4）。家属端日常操作全部留审计。

## 8. 事务与幂等

| 操作 | 事务 | 幂等 |
|---|---|---|
| 单条删除 | 标记 + 任务 + 审计 | 天然幂等（重复删返回成功） |
| 清空 | 批量标记 + 任务 + 审计 | 天然幂等 |
| 注销申请 | 状态 + 冷静期 + 解绑 | 重复申请返回已有冷静期 |
| 撤销注销 | 状态回滚 | 幂等 |
| 导出 | 创建任务 | 需 `Idempotency-Key`（防重复打包） |

---

## 9. 队列

| 队列 | 任务 | 重试 | 死信 |
|---|---|---|---|
| `cleanup` | 删除音频、硬删除记录、到期清理、导出产物清理 | 5 次，指数退避 | **必须告警** |
| `export` | 打包导出产物 | 3 次 | 告警 |
| `purge` | 账号彻底删除 | 5 次 | **必须告警** |

**`purge` 队列的死信是最高优先级告警。** 注销没删干净是合规事故。

## 10. 缓存

| 键 | TTL | 失效 |
|---|---|---|
| 权限判定 | 1 分钟 | 删除/注销时主动删除 |
| 同意状态 | 1 分钟 | 撤回时主动删除 |
| 导出产物链接 | 不缓存 | — |

**删除与注销必须主动清缓存**，不能等 TTL 过期。

## 11. 审计（本模块的核心产出）

| 必须审计 | 字段 |
|---|---|
| 音频读取 | actorId、recordId、时间、IP 摘要 |
| 导出（含摘要与全量） | actorId、scope、时间 |
| 同意授予 / 撤回 | 类型、版本、时间 |
| 删除（单条 / 清空 / 注销） | actorId、范围、时间、任务 ID |
| 管理员访问 | actorId、目标、时间、**目的（必填）** |
| 留存期限变更 | 旧值、新值、操作者 |

**保留 12 个月**，不可被业务代码修改或删除。

**用户可查**：本人可查询涉及自己的审计记录——`GET /v1/audit-logs`（见 `../../api/API-05-导出与注销.md` 5.10，2026-09-28 补）。响应只含操作类型/目标/时间，内部字段不外露。管理员全量查询走运营后台。

**禁止记录**：音频内容、转写全文、手机号明文、令牌、密钥。

## 12. 异常处理

| 异常 | 处理 |
|---|---|
| 删除时对象存储不可用 | 任务重试；重试耗尽进死信 + **高优先级告警** |
| 删除时记录已不存在 | 视为成功（幂等） |
| 注销时网络/服务异常 | 客户端本地已清除；服务端任务持久化，恢复后继续 |
| 导出体积过大 | 提示分批；不静默截断 |
| 导出产物生成失败 | 重试；失败后明确告知用户 |
| 清理任务积压 | 告警 |
| 到期清理漏删 | 对象存储生命周期规则兜底（4.1） |

| # | 要求 |
|---|---|
| 1 | 删除是**硬删除**，对象本体必须消失 |

## 15. 验收标准

- [ ] 留存期限可见可调，默认 24 个月（FR-6.6）
- [ ] 隐私政策写明**具体天数**，不写"合理期限"
- [ ] 三层清理机制全部实现（应用层 + 对象存储生命周期 + 数据库兜底）
- [ ] 删除是**硬删除**，对象存储中确实消失（E2E-08）
- [ ] 删除后触发基线重算
- [ ] 删除操作有审计记录
- [ ] 清空全部记录**仅本人可执行**（2.5）
- [ ] 注销有 7 天冷静期，可撤销
- [ ] 注销幂等且彻底，所有接口都无法再访问（E2E-09）
- [ ] 注销时立即解绑，他人立即无法访问
- [ ] 导出产物 24 小时必删
- [ ] 导出文件不含 `zScore` / 均值 / 标准差 / 量表分数
- [ ] **服务端不存在面向医生的临床输出接口**（6.2 / E2E-07）
- [ ] 删除/注销/导出队列的死信**必须有告警**
- [ ] 审计日志保留 12 个月，不可被业务代码修改
- [ ] 备份轮转 ≤30 天，副本处理方式在隐私政策中说明
- [ ] 删除与注销立即清缓存，无访问延迟窗口
- [ ] 撤回同意后立即不可访问，无缓存窗口
- [ ] 运营管理员无音频读权限（数据层验证）
