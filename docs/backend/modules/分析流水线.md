# 后端模块：分析流水线

**覆盖需求**：FR-2
**对应接口**：`../../api/API-02-录音与上传.md`（状态轮询）、`../../api/API-03-指标与趋势.md`（结果读取）

> **⚠️ 2026-09-28 重构（C5）**：声学指标由客户端本地计算改为**云端 worker 统一计算**，与 ASR 合并为一条流水线。登记接口不再接收客户端声学指标。指标口径与论文实验代码同语言（Python + DSP 库），天然一致。

---

## 1. 职责边界

### 1.1 职责

音频上传完成后，在云端 worker 内**统一计算声学指标与文本指标**：先算声学指标（不依赖 ASR，必得），再调 ASR 转写并计算文本指标，最后质量门控并写库。

### 1.2 不做什么

| 不做 | 理由 |
|---|---|
| **不做端侧指标** | 声学指标已上收云端（C5，2026-09-28），客户端只录音不算指标 |
| **不做 AD 分类 / MMSE 预测** | 模型在论文侧离线跑，**不进产品链路**（见 `../../PROJECT_REQUIREMENTS.md` 1.3） |
| 不做音频内容审核 | 音频不公开，无审核场景 |
| 不做说话人识别 / 声纹 | X-3 |
| 不做实时流式识别 | 场景是异步批处理，无实时需求 |
| 不做跨记录的语言模型微调 | 一期不做 |

### 1.3 最重要的一条边界

**分析流水线的输出永远只是"指标数值"，永远不是"结论"。**

流水线不产生任何"正常/异常/风险"判断，也不产生任何面向用户的文字。**判断在基线与状态机模块，文案在前端。** 这条边界如果被打破，整个合规设计就崩了。

## 2. 领域对象

```
AnalysisJob
├── jobId
├── recordId
├── subjectId
├── state            # PENDING | ANALYZING | DONE | FAILED
├── attempts
├── asrEngine        # 记录用的哪家 ASR，便于口径追溯
├── asrModelVersion
├── dspLibVersion    # 声学指标计算库版本（口径追溯，同论文实验对齐）
├── startedAt / finishedAt
└── failureReason

AcousticMetrics         # 云端计算（C5，2026-09-28 起）
├── recordId
├── speechRate          # 语速
├── pauseRatio          # 停顿率（流畅度）
├── longPauseCount
├── snrDb               # 信噪比（质量门控输入）
├── silenceRatio        # 静音比（质量门控输入）
└── computedBy          # WORKER（固定值，预留端侧扩展位）

AsrResult
├── recordId
├── text
├── confidence       # 整体置信度
├── segments[]       # 分段（时间戳 + 文本 + 置信度）
├── dialect
├── engine
└── modelVersion

TextMetrics
├── recordId
├── mattr            # 移动平均类符形符比
├── meanSentenceLen
├── connectiveRate
├── rareWordRatio
├── contentFunctionRatio
├── propositionDensity
└── computedFrom     # ASR | MANUAL（人工转录）

QualityGate
├── recordId
├── snrDb
├── durationSec
├── silenceRatio
├── asrConfidence
├── flag             # VALID | SUSPECT | INVALID
└── reasons[]
```

**`computedFrom` 字段是刚需**：论文训练用人工转录，产品用 ASR 输出，两者口径不同。必须能区分（见 `../../PROJECT_REQUIREMENTS.md` 4.3 指标断层警告）。

## 3. 状态机

```
PENDING ──worker 取任务──▶ ANALYZING ──成功──▶ DONE
                              │
                              ├──可重试错误──▶ PENDING（attempts+1）
                              │
                              └──不可重试 / 重试耗尽──▶ FAILED
```

| 状态 | 客户端表现 |
|---|---|
| `PENDING` | 前端显示"正在分析"，无指标可用（声学也已上收云端，客户端不再有即时结果） |
| `ANALYZING` | 同上 |
| `DONE` | 全部指标可用 |
| `FAILED` | 视失败阶段降级（见 10.1） |

**降级优于作废**：流水线内部按"声学先算（必得）→ ASR 后跑（可败）"排序，ASR 失败时声学指标已经写库，只丢文本指标。

---

## 4. 处理流程

```
worker 从 analysis 队列取任务
  ↓
1. 校验记录仍存在且未被删除（幂等前提）
  ↓
2. 从对象存储下载音频到临时空间（用服务端凭证，非签名 URL）
  ↓
3. 声学指标计算（先算，不依赖 ASR —— 必得）
     ├─ 语速、停顿率、长停顿数（DSP：librosa / webrtcvad）
     ├─ snrDb、silenceRatio（质量门控输入）
     └─ 失败 → 音频大概率损坏，走降级（10.1 最底层）
  ↓
4. 调用境内 ASR
     ├─ 成功 → AsrResult（含置信度）
     └─ 失败 → 判断是否可重试（可重试时声学指标已写库，不受影响）
  ↓
5. 文本指标计算（在 ASR 文本上）
     ├─ MATTR（不用 TTR，短样本 TTR 极不稳）
     ├─ 平均句长
     ├─ 连接词率
     └─ 其他
  ↓
6. 质量门控（snrDb / durationSec / silenceRatio / asrConfidence）
  ↓
7. 写入指标（事务内）+ 触发基线与状态机重算
  ↓
8. 删除临时音频文件（必须，不留副本）
```

**第 3 步在 ASR 之前**是刻意排序：声学指标不依赖 ASR，先算先写库，ASR 无论成败都拿得到声学结果。这是 C5 上收云端后降级逻辑反而更稳的原因。

**第 8 步容易被漏掉。** 临时文件如果没删，等于在业务服务器上又存了一份音频副本，破坏了"音频只存在对象存储"的合规设计。

## 5. 权限

分析流水线是**内部服务身份（`SYSTEM`）**，不面向用户。

| 要求 | 说明 |
|---|---|
| 无用户可调用入口 | 只能由队列触发，不暴露 HTTP 端点 |
| 服务凭证独立 | 不与用户令牌共用 |
| 对象存储凭证最小权限 | 只读音频桶，不能删（删除由 cleanup 队列做） |
| 不能访问临床量表 | 分析不涉及量表数据 |

## 6. 事务与幂等

| 操作 | 事务 | 幂等 |
|---|---|---|
| 取任务 | 无 | 需**加锁**防重复消费（同 recordId 只处理一次） |
| 写入指标 | 指标 + 记录状态 + 状态机重算（同一事务） | 同 recordId 重复写入应覆盖而非追加 |
| 标记失败 | 记录状态 + failureReason | 天然幂等 |

### 6.1 重复消费的处理（重要）

队列可能重复投递。**必须以 `recordId` 为幂等键**：

```
if (记录已是 DONE 且指标存在) → 直接返回，不重算
```

否则会出现：同一记录被算两次，指标表出现两行，趋势图出现重复点。

**实现建议**：`TextMetrics.recordId` 加唯一约束。这是最简单可靠的兜底。

## 7. 队列与重试

| 参数 | 值 |
|---|---|
| 队列 | `analysis` |
| 最大重试 | 3 |
| 退避 | 指数（10s / 60s / 300s） |
| 超时 | 单任务 120 秒 |
| 并发 | 按 ASR 服务配额设定，不超过配额 |
| 死信 | 重试耗尽进死信队列 + 告警 |

### 7.1 可重试 vs 不可重试

| 错误类型 | 可重试 |
|---|---|
| ASR 超时 | ✅ |
| ASR 限流（429） | ✅（退避后） |
| 网络抖动 | ✅ |
| ASR 返回格式错误 | ✅（可能是临时问题，但 3 次后放弃） |
| 音频格式不支持 | ❌ |
| 音频文件不存在 | ❌ |
| 记录已被删除 | ❌（直接结束，不算失败） |
| 权限/凭证错误 | ❌（需人工介入，必须告警） |

**"记录已被删除"必须是正常结束**，不是失败。否则用户删记录后会收到一堆分析失败告警。

---

## 8. 缓存

| 键 | 内容 | TTL |
|---|---|---|
| `asr:{recordId}` | ASR 结果 | 24 小时（便于重试时不重复调用 ASR，省钱） |
| 指标 | 不单独缓存 | 随记录缓存 |

**ASR 结果缓存 24 小时**：重试时如果 ASR 已经成功、只是后续步骤失败，可以复用结果，避免重复计费。这是实打实的成本优化。

## 9. 审计

| 事件 | 记录 |
|---|---|
| 任务开始 / 结束 | jobId、recordId、耗时、ASR 引擎与版本 |
| 失败 | 错误类型、attempts、是否进死信 |
| 降级 | 文本指标置空的原因 |

**禁止记录**：ASR 全文、音频内容。

## 10. 异常处理

| 异常 | 处理 |
|---|---|
| ASR 超时 | 重试；耗尽后 `FAILED`，保留声学指标 |
| ASR 限流 | 退避重试 |
| ASR 返回低置信度 | **不重试**，走质量门控，标记 `SUSPECT` |
| 音频不存在 | `FAILED`，告警（说明数据不一致） |
| 记录已删除 | 正常结束，不告警 |
| 文本指标计算异常 | `FAILED`；但声学指标仍保留 |
| 临时文件写入失败 | `FAILED`，告警（磁盘问题） |
| 队列积压 | 告警（NFR-6.4） |

### 10.1 降级原则

**任何环节失败都不能让整条记录作废。** 降级顺序（C5 后按流水线阶段重排）：

```
完整结果（声学 + 文本）
  ↓ ASR 失败 / 文本指标失败
仅声学指标 + 文本指标置 null        ← 声学已先算先写库（第 3 步）
  ↓ 声学指标也失败（音频损坏等极端情况）
记录保留，标记 INVALID，不参与趋势
```

**最底层的保底**：记录本身（音频 + 元数据）永远保留，用户不会"白录"（UR-06）。

**与旧版的差别**：旧版声学指标在端侧"天然必得"；新版声学在云端第 3 步先算先写，**ASR 失败只影响文本指标**，降级形状不变、可靠性不变。

## 11. 安全

| # | 要求 |
|---|---|
| 1 | ASR 服务必须**境内**，出站白名单（SEC-12） |
| 2 | 临时音频文件：加密落盘、用后立即删除、崩溃恢复时清理残留 |
| 3 | 服务凭证独立于用户令牌 |
| 4 | 对象存储凭证最小权限（只读） |
| 5 | 不记录 ASR 全文到日志 |
| 6 | 不把音频或转写发给任何第三方（除境内 ASR 服务商，且需在隐私政策中披露） |
| 7 | ASR 服务商需签数据处理协议，禁止其留存或用于训练 |

**第 7 条是谈判要点**：很多 ASR 服务默认会用调用数据做模型优化。必须在合同或配置中关闭，并写入隐私政策。

## 12. 测试

| 类型 | 覆盖 |
|---|---|
| 单元 | 文本指标计算（对照标准实现）、质量门控阈值、可重试判定 |
| 集成 | 上传 → 队列 → ASR（Mock）→ 指标 → 状态机 全链路 |
| **幂等测试** | 同一 recordId 投递 10 次，断言指标表只有 1 行 |
| 失败注入 | ASR 超时 / 限流 / 格式错误 / 音频缺失 / 记录已删 |
| 降级测试 | ASR 失败后断言声学指标仍在、文本指标为 null |
| 临时文件测试 | 任务结束后断言临时目录为空；崩溃后重启能清理残留 |
| 成本测试 | 重试时复用 ASR 缓存，断言不重复调用 |

## 13. 验收标准

- [ ] 声学指标在云端 worker 计算（C5），登记接口不接受客户端指标字段
- [ ] 声学指标在 ASR 之前计算并先写库，ASR 失败不影响声学结果
- [ ] `dspLibVersion` 与 `asrEngine/asrModelVersion` 入库，指标口径可追溯
- [ ] ASR 在云端异步执行，1 分钟音频 ≤60 秒返回（FR-2.2 时效随 C5 调整为网络往返）
- [ ] ASR 失败时**保留声学指标**，文本指标置 `null`，不整条作废（FR-2.2）
- [ ] 文本指标标注 `computedFrom`，能区分 ASR 与人工转录（FR-2.3）
- [ ] MATTR 而非 TTR（FR-2.3）
- [ ] 质量门控按 `../../PROJECT_REQUIREMENTS.md` 5.3 生效（FR-2.4）
- [ ] 不合格记录**保留但不参与趋势计算**（FR-2.4 / 5.3）
- [ ] 同 recordId 重复消费不产生重复指标（幂等测试）
- [ ] 记录已删除时任务正常结束，不产生失败告警
- [ ] 临时音频文件用后立即删除，无残留
- [ ] **流水线不产生任何"结论"或面向用户的文字**（1.3 边界）
- [ ] **流水线不做 AD 分类或 MMSE 预测**（X-1 / X-2）
- [ ] ASR 服务境内，出站白名单验证通过（SEC-12）
- [ ] ASR 服务商不留存、不用于训练（合同或配置验证）
- [ ] 日志中无 ASR 全文
- [ ] 队列死信有告警（NFR-6.4）
