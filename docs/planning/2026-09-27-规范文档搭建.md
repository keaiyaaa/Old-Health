## 6. 本轮的实质性设计决策

这些不是文档搬运，是新增的设计判断：

| # | 决策 | 理由 |
|---|---|---|
| D1 | **就诊摘要在客户端本地生成**，服务端不提供任何临床输出接口 | 只要服务端存在这样的接口，就构成"给出临床诊断治疗依据和/或建议的决策支持软件"，落入第三类医疗器械。把摘要生成放客户端是**合规设计**，不只是架构选择 |
| D2 | **偏离程度用 `zBand` 分档返回，不给 z 分数** | 前端需要知道"是否偏离"，不需要知道"偏离多少"。分档消除了解读空间，且阈值在服务端、前端无从反推 |
| D3 | **老人端趋势走独立接口** `/metrics/{id}/plain`，只返回方向与文字 | 用接口设计保证红线——即使前端有 bug 也拿不到数值，而不是靠前端自觉 |
| D4 | **S4/S5 缺非疾病解释时接口返回 500 并告警** | 宁可页面挂掉被立刻发现，也不能让没有非疾病解释的"变化"提示流到用户面前。**失败要响，不要静** |
| D5 | **越权统一返回 404，唯一例外是"同意未授予"返回 403** | 403 会泄露资源存在性；但同意未授予必须明确告知，否则用户卡住不知为何 |
| D6 | **权限模型拆成身份 / 绑定 / 同意三种授权来源** | 三种授权的生命周期与撤回后果完全不同，合并会做错 |
| D7 | **只存年龄段，不存精确生日** | 最小必要原则；精确年龄对分析无增量价值，但显著提高敏感度 |
| D8 | **基线按 `taskType` 分组计算** | `DAILY_FREE` 与 `WEEKLY_PICTURE` 的语速天然不同，混合会把任务差异误判为变化 |
| D9 | **声学与文本基线分别报告 `isEstablished`** | 文本指标依赖 ASR，建立速度慢，会出现"声学已建立、文本未建立"的中间态 |
| D10 | **删除后必须触发基线重算** | 删掉记录后基线不变，会让状态判定基于已不存在的样本 |
| D11 | **三层清理机制**（应用层 + 对象存储生命周期 + 数据库兜底） | 应用层会因故障漏删，对象存储生命周期规则是存储侧保证的最后防线 |
| D12 | **隐私政策必须写明备份副本的处理方式** | 备份中的副本无法单条删除。装作没有才是风险 |
| D13 | **ASR 结果缓存 24 小时** | 重试时若 ASR 已成功只是后续步骤失败，可复用结果，避免重复计费 |
| D14 | **`recorderRole` 必填** | 论文取数必须能区分老人自录与家属代录，否则数据可用性受损 |
| D15 | **OpenAPI 现在不手写** | 后端未选型时手写契约，选型后必然重写；且手写契约会与实现分叉，比没有更糟 |

**导航型引用的定义**：Markdown 链接 `[x](path)` + 反引号内以 `./` 或 `../` 开头的相对路径。

**不计入的**：叙述型引用（如 `` `docs/api/` `` 这类仓库根相对路径、`` `{subjectId}/` `` 这类路径模板、`` `../API-0x-*.md` `` 这类通配符、以及历史文件名）。它们不是导航链接，语义上也不需要可解析。
